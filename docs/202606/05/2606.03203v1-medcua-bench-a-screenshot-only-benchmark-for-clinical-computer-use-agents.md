## 摘要
计算机使用智能体能够自动化重复的基于屏幕的临床工作，但其在医疗图形用户界面中的可靠性尚未得到充分验证。现有基准测试主要关注通用网页或桌面任务，未能充分涵盖医疗软件，后者需要领域知识，其用户界面设计明显不同于主流应用，缺乏公共测试环境，且需要超出任务完成范围的安全验证。我们提出了MedCUA-Bench，一个面向临床计算机使用智能体的交互式基准测试。它涵盖了10个医疗领域的18个临床场景，依据真实产品手册和开源医疗系统重建，以捕捉真实的临床界面，同时避免许可和隐私限制。每个任务都配有成对的目标层与步骤层目标，以将临床推理与用户界面执行分离，并通过确定性检查器评估任务完成情况以及五个临床安全维度。在23个智能体中，最好的闭源模型达到54.2%的严格成功率，而所有模型在真实OpenEMR上的成功率均低于9%。开源智能体平均仅为2.5%，最佳达到16.2%。MedCUA-Bench揭示了当前智能体与可靠临床软件使用之间的差距，为未来研究提供了一个可复现的测试平台。

## Abstract
Computer-use agents could automate repetitive screen-based clinical work, but their reliability in medical graphical user interfaces remains largely unvalidated. Existing benchmarks focus on general web or desktop tasks and underrepresent medical software, which requires domain knowledge, exhibits markedly different UI design from mainstream applications, lacks public testing environments, and demands safety validation beyond task completion. We introduce MedCUA-Bench, an interactive benchmark for clinical computer-use agents. It covers 18 clinical scenarios across 10 medical domains, reconstructed from real product manuals and open-source medical systems to capture authentic clinical interfaces while avoiding licensing and privacy constraints. Each task ships with paired intent- and step-level goals to disentangle clinical reasoning from UI execution, and is evaluated by a deterministic checker over task completion and five clinical safety dimensions. Across 23 agents, the best closed-source model reaches 54.2% strict success, while all models remain below 9% on the real OpenEMR. Open-source agents average only 2.5%, with the best reaching 16.2%. MedCUA-Bench exposes the gap between current agents and reliable clinical software use, providing a reproducible testbed for future research.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：计算机使用代理（CUA）有望自动化医生在电子健康记录（EHR）等临床软件中的重复性操作，从而减轻职业倦怠。但现有CUA基准测试（如WebArena、OSWorld、ScienceBoard）主要面向通用网页或桌面应用，忽略了医疗软件的特殊性。
- **核心问题**：临床环境的四大特点使通用基准无法衡量CUA的可靠性：
  - **领域知识需求**：医疗GUI充满专业术语、患者信息和特殊操作顺序。
  - **独特UI设计**：医疗软件采用陈旧布局、密集表单和独特控件，与现代应用差异大。
  - **无法公开测试**：真实系统受法规、隐私和许可限制，无法提供API、DOM树或可公开部署的环境。
  - **安全性要求**：即使外观上完成任务，也可能存在错误患者、错误数据、工作流违规等临床危害，但现有二值成功率指标无法捕捉。
- **整体含义**：缺乏针对医疗GUI的CUA基准，严重阻碍了临床自动化代理的可靠性与安全评估。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：构建一个**可交互的、仅基于截图**的医疗GUI基准，以便在无API/隐私泄露风险下，对CUA进行临床现实的安全感知评估。
- **技术细节**：
  - **场景构建**：18个临床场景，覆盖10个医疗领域（门诊、住院、ICU、护理、影像等）。其中15个为**合成HTML界面**（依据产品手册重建），1个为**真实OpenEMR v7.0.2**（Docker部署），2个为**真实OHIF Viewer**（DICOM影像）。合成场景保留真实系统的工作流、布局和交互模式，但无专有代码或商标。
  - **任务设计**：每个基础任务配有**两个目标粒度**：
    - **意图目标（Intent Goal）**：高层临床目标，如“记录患者的生命体征”。
    - **步骤目标（Step Goal）**：具体的点击/输入过程，如“点击[生命体征]标签→输入心率102→点击保存”。
    - 同一环境与检查器，仅提示的细化程度不同，从而分离临床推理失败与UI执行失败。
  - **代理接口**：代理在每一步只接收页面截图、当前目标、历史动作及上一步的错误信息。动作空间为低层鼠标点击（整数坐标）、键盘输入、滚动等。不允许使用DOM、HTML或set-of-marks，完全依赖像素级理解。
  - **安全评估与奖励**：
    - 确定性检查器比较最终页面状态、网络请求、导航历史与预期值，输出严格完成标志、进度向量和**五个安全维度**（患者身份、数据准确性、信息保真度、记录完整性、工作流安全性）的违规列表。
    - 违规分三个严重级别：Critical（权重1.0）、Major（0.3）、Minor（0.05）。Critical违规立即终止回合。
    - 回合奖励：**r = clamp(stask − Σw(v), −1, +1)**，其中stask ∈ {0,1}为严格完成标志，w(v)为违规权重。干净的完成得+1，带有违规的完成会被扣分甚至为负。

### 3. 实验设计：使用的数据集/场景、Benchmark、对比方法

- **数据集/场景**：MedCUA-Bench包含：
  - 18个临床场景（合成×15、OpenEMR×1、OHIF×2），对应216个基础任务。
  - 每个任务注册两种目标粒度（意图、步骤），共计432个评估实例。
  - 任务难度分为易（67个）、中（76个）、难（73个）。
- **Benchmark**：专门为此设计的交互式环境，使用BrowserGym框架统一接口。
- **对比方法**：评估了23个视觉CUA，其中：
  - **闭源模型（6个）**：GPT-5.4、Claude-Opus-4.7、Claude-Sonnet-4.6、Kimi-K2.6、GPT-5-Mini、Gemini-3.1-Pro。
  - **开源模型（17个）**：Qwen2.5-VL-32B/72B-AWQ、InternVL3.5-14B/8B、Gemma-3-27B、Qwen3.5-27B/9B、Phi-4-Multimodal、Kimi-VL-A3B、Gemma-4-E4B、A3-Qwen3.5-9B、OpenCUA-7B/32B，以及4个零成功率的模型（GLM-4.1V-9B、Idefics3-8B、Fara-7B、UI-TARS-7B-DPO）。
- **协议**：所有代理使用同一AgentLab框架，仅截图输入，30步预算，单次运行（无重复）。主要指标为严格成功率、安全感知奖励、截断率、平均步数等。

### 4. 资源与算力

- **文中明确说明**：
  - 开源模型使用**vLLM v0.20.2**部署，每个模型运行在**单个A100 80GB GPU**上，部分模型使用`enforce-eager`模式。Qwen2.5-VL-72B使用AWQ 4-bit量化以符合单GPU预算。
  - 闭源模型通过各自官方API调用（OpenAI、Anthropic、Google、Moonshot等）。
- **未明确给出总训练算力**（因为此项工作为评估而非训练），但提供了附录B的**推理耗时**（如GPT-5.4平均73.2秒/任务，总8.8小时；Qwen2.5-VL-32B平均1137秒/任务，总136.5小时）。未提及训练阶段算力。

### 5. 实验数量与充分性

- **实验数量**：
  - 23个代理 × 432个任务 = **9936个回合**。
  - 每个代理仅运行一次（缺乏多次随机重复），点估计而非统计置信区间。
  - 人类基线仅**24个任务**的试点（单操作员，6个场景×{中/难}×{意图/步骤}），成功率为83.3%。
- **充分性与公平性**：
  - 优点：覆盖多领域、多难度、多页面类型（合成/真实EHR/真实影像），以及两种目标粒度；统一测试框架；确定性检查器保证可重复。
  - 不足：单次运行无法反映方差；人类基线样本量小，非多注释者；闭环决策可靠性指标未完全测试（安全违规少，因多数代理超时而非错误完成）。作者坦诚“安全检查器在当前能力下未充分训练”。

### 6. 论文的主要结论与发现

- **当前CUA远未达到临床可靠**：
  - 最佳闭源模型GPT-5.4仅**54.2%**严格成功率，Claude-Opus-4.7为52.6%。
  - 在真实OpenEMR上，所有模型低于**9%**（GPT-5.4、Claude系列均为8.3%，Kimi为0%）。
  - 开源模型平均仅**2.5%**，最佳Qwen2.5-VL-32B为16.2%。
- **页面保真度差异巨大**：合成界面表现最好（GPT-5.4达54.7%），真实EHR几乎全军覆没，影像界面开源模型接近闭源（例如Qwen2.5-VL-72B-AWQ达45.8%）。
- **目标粒度效果**：强模型在步骤目标下均提升约3-5个百分点（如GPT-5.4从51.9%升至56.5%），表明许多失败源于执行而非推理。弱模型反而下降，说明长提示增加了负担。
- **失败模式**：主要失败是**步预算超时**（43-99%的回合），而非错误完成或安全违规。闭源模型多为探索超时，开源模型多为格式锁定或重度循环。安全违规极少（零Critical，53 Major，15 Minor），但这是因为代理通常无法到达危险操作点。
- **像素级定位是当前瓶颈**：Gemini-3.1-Pro格式输出良好但成功率仅4.6%，说明其像素定位能力远弱于GPT-5.4。

### 7. 优点

- **领域针对性**：首个面向完整临床工作流的可执行GUI基准，覆盖多个医疗领域和真实系统，填补了空白。
- **双粒度目标设计**：有效区分推理失败与执行失败，为诊断代理瓶颈提供直接依据。
- **确定性安全检查**：包含五个临床安全维度和严重性权重，能捕捉“表面成功但临床危险”的情况。
- **页面多样性**：合成界面、真实EHR、真实影像三种保真度，揭示模型在不同界面类型上的能力差异。
- **大量模型评估**：评估了23个模型（含多种闭源和开源系列），结果具有较强代表性。
- **可复现性**：基于开源工具（BrowserGym、OpenEMR、OHIF）构建，将开源代码与测试集，便于后续研究。

### 8. 不足与局限

- **实验覆盖**：
  - 每个任务仅单次运行，缺乏统计稳定性。
  - 人类基线仅24个任务试点，非多注释者完整评估。
  - 合成场景未完全复现原始系统的视觉外观，成功率可能高估。
- **偏差风险**：
  - 当前能力下安全检查器未充分训练（多数代理超时），零Critical违规不反应实际安全性。
  - 仅支持截图输入，未考虑DOM/辅助技术是否能提升性能（作者有意识限制，但通用性受限）。
- **应用限制**：
  - 工作流限于文档操作，未覆盖语音、多模态交互或复杂临床决策。
  - 30步预算可能限制需要更多步骤的长任务，但作者分析显示成功任务平均步数低于20，预算非瓶颈。
  - 未进行多回合交互或跨会话任务。
- **伦理说明**：无真实患者数据，但论文强**高分数不代表临床部署就绪**，必须经过独立验证、监管审查和人工监督。
