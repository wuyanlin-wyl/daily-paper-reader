### 1. A Vision-language Framework for Comparative Reasoning in Radiology
- 区域：deep；分数：10.0
- 原文链接：https://arxiv.org/abs/2606.06407v1
- 方法流程：
  - 数据构建：从临床图像-报告对中提取实体级标注（解剖结构、异常发现、病理条件），构建三元组排序样本和比较VQA样本
  - 实体感知对比训练：使用文本引导的对比排序损失，训练MoE ViT编码器生成实体条件视觉表示
  - 检索推理：给定查询图像和实体，计算查询实体特征与候选图像实体特征的相似度，返回Top-K
  - 生成推理：将查询图像对（当前与历史）的实体条件视觉特征通过交叉注意力注入LLM，生成比较描述
- 关键模块/机制：
  - MoE ViT：模态感知视觉编码器，处理不同成像模态（X光、CT、MRI、超声）的图像特征提取；基于视觉Transformer，使用混合专家（MoE）层，每个专家专门处理一种模态，输入图像通过路由选择相应专家，输出共享维度的视觉token序列
  - 实体编码器：将临床实体（如'lung'）编码为条件向量，用于引导视觉注意力；使用预训练文本编码器（如BERT）将实体名称编码为嵌入向量，与图像特征通过交叉注意力融合
  - 跨图像交叉注意力：对齐参考图像对或时序图像对中的实体相关区域；在MedReCo-VLM中，将当前图像的实体条件视觉特征作为query，历史图像特征作为key/value，通过多头注意力计算对应关系
  - 大语言模型（LLM）：生成自然语言比较描述（如'双侧肺野透亮度增加'）；基于指令微调的预训练LLM（如LLaMA），接受融合后的视觉特征和问题文本，自回归生成答案
- 公式/目标函数/指标定义：
  - 输入信息未提供明确公式
- 算法细节：
  - 实体条件对比学习：构造正负样本三元组（查询图像、实体、正候选、负候选），使用InfoNCE损失最大化正样本相似度，最小化负样本相似度
  - 跨图像交叉注意力机制：当前图像实体token与历史图像所有token计算注意力权重，加权聚合得到比较特征
  - 模态路由：MoE ViT中每个专家对应一种模态，输入图像通过轻量级分类器选择Top-2专家，输出加权融合
- 训练/推理细节：
  - 预训练阶段：在MedReCo-DB上使用对比损失训练MoE ViT和实体编码器，不冻结任何参数
  - 指令微调阶段：冻结MoE ViT，训练交叉注意力投影层和LLM，使用比较VQA数据（图像对、实体、问题、答案）
  - 推理时，检索使用余弦相似度；生成使用自回归解码，temperature=0.2
  - 训练使用4×A100 GPU，batch size 256，学习率1e-4（预训练）和1e-5（微调）

### 2. RL-ACRGNet: Reinforcement Learning-Based Chest Radiology Report Generation Network
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2606.02035v1
- 方法流程：
  - 输入：CXR图像（如IU-Xray或MIMIC-CXR）
  - 编码：使用预训练DenseNet提取深度视觉特征
  - 解码：多级LSTM逐步生成报告文本，每步根据前一状态和视觉特征预测下一个词
  - 强化学习训练：采用off-policy actor-critic方法，agent（policy网络）依据状态生成动作（词），critic（value网络）评估序列价值，reward网络基于复合奖励函数（BLEU等）提供即时和最终奖励
  - 输出：完整的放射学报告文本
- 关键模块/机制：
  - DenseNet编码器：从CXR图像中提取高维视觉特征，通过密集连接捕获多尺度细节；使用ImageNet预训练的DenseNet作为CNN编码器，网络包含多种卷积核（1×1至7×7）和分组配置，输出特征图作为后续解码器的视觉输入
  - 多级LSTM解码器：生成层次化、连贯的报告文本，捕获词间长距离依赖；包含多个LSTM层级，逐步生成句子序列；每个时间步结合视觉特征和前一时刻隐藏状态预测当前词概率
  - Policy网络（Actor）：根据当前状态（图像特征和已生成词）选择下一个词（动作）；以softmax输出词表上的概率分布，通过最大化期望累积奖励进行优化
  - Value网络（Critic）：评估当前状态或动作的长期价值（期望回报），指导policy更新；输出标量价值函数，用于计算优势函数，减少策略梯度方差
  - Reward网络：对部分生成的报告提供即时评分，辅助训练policy和value网络；采用复合奖励函数，线性加权BLEU-4、METEOR、ROUGE-L等指标，直接反映报告质量
- 公式/目标函数/指标定义：
  - 输入信息未提供明确公式，但可推断目标函数为最大化期望累积奖励，其中奖励函数为复合NLP指标线性组合：R = α·BLEU + β·METEOR + γ·ROUGE-L（系数未给出）
- 算法细节：
  - 离策略actor-critic：使用经验回放（buffer）存储历史轨迹，从buffer中采样更新网络，提高样本效率
  - 双网络更新：policy网络通过策略梯度（如PPO）更新，value网络通过最小化均方误差（预测价值与实际回报）更新
  - 复合奖励计算：每生成一个完整报告或部分句子时，由reward网络计算BLEU-4、METEOR、ROUGE-L的加权和作为奖励信号
- 训练/推理细节：
  - 训练：分两阶段，先使用交叉熵损失预训练编码器-解码器（teacher forcing），再使用强化学习（actor-critic）微调，优化复合奖励
  - 优化器：Adam，学习率等超参数未提供
  - 推理：采用beam search或贪心解码，从DenseNet提取特征后由LSTM逐步生成，无强化学习干预
  - 数据集：IU-Xray（小规模）和MIMIC-CXR（大规模），图像预处理包括归一化和裁剪

### 3. MedCUA-Bench: A Screenshot-Only Benchmark for Clinical Computer-Use Agents
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2606.03203v1
- 方法流程：
  - 阶段1: 环境构建——从产品手册和开源系统重建15个阴影GUI，部署OpenEMR和OHIF Viewer作为真实环境
  - 阶段2: 任务生成——为每个场景定义种子（患者数据、检查参数等），生成预期值字典和确定性检查器
  - 阶段3: 双目标设计——为每个任务生成意图级目标（高级临床目标）和步骤级目标（逐步操作过程）
  - 阶段4: 代理交互——代理接收截图、目标、历史动作和错误信息，输出低级操作（鼠标点击、键盘输入等）
  - 阶段5: 评估——确定性检查器通过比较最终页面状态与预期值，计算任务成功率和五个安全维度的得分
- 关键模块/机制：
  - BrowserGym环境：提供可交互的GUI环境；每个场景实现为BrowserGym环境，支持像素级交互（截图输入，点击/键盘输出），并记录网络请求和页面状态供检查器审计。
  - 任务生成器：生成带有种子、预期值和检查器的任务；基于场景定义种子（如患者ID、生命体征等），生成期望值字典（如正确录入的数据），并为每个任务创建确定性检查函数。
  - 双目标机制：分离临床推理与UI执行；每个base task有两个自然语言目标：intent goal（高级临床目标，如'记录分诊评估'）和step goal（详细分步操作，包括字段和按钮）。环境与检查器相同，仅提示不同。
  - 确定性检查器：评估任务完成和安全性；检查器基于最终页面状态、网络请求和聊天响应的预期值，计算任务成功率和五个安全维度的得分。安全维度包括患者身份、数据准确性、信息保真度、记录完整性、工作流安全，可使用严重性权重分配负奖励。

### 4. CP-Agent: Context-Aware Multimodal Reasoning for Cellular Morphological Profiling under Chemical Perturbations
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2606.03435v1
- 方法流程：
  - 1. 图像预处理：对每个荧光通道独立应用CLAHE、随机拉普拉斯锐化、伽马校正，裁剪为512×512图块，扰动图块与对照图块沿通道维度拼接。
  - 2. 分子编码：使用固定维度映射（物理化学和拓扑描述符）提取化合物特征向量，z-score归一化；计算归一化剂量对[ρ_max, s(C)]和时间值。
  - 3. 文本构建：将实验元数据组成自然语言句子，插入特定占位符令牌<CMPD>, <CONC>, <TIME>，通过GPT-2 tokenizer生成输入ID。
  - 4. 令牌投影：通过字段特定MLP（f_cmpd, f_conc, f_time）将结构化描述符投射为嵌入，替换占位符位置的嵌入。
  - 5. 对比学习：使用CLIP-style对比损失，对齐图像嵌入（ViT）和文本嵌入（GPT-2），训练1.9M图像-上下文对。
  - 6. 推理与报告生成：将CP-CLIP输出作为感知层，集成工具使用和MoA本体，由MLLM生成结构化药物筛选报告。
- 关键模块/机制：
  - CP-CLIP：上下文感知的图像-文本对齐模块，提供感知基础；使用对比学习框架，图像分支采用ViT编码配对的扰动-对照拼接图，文本分支使用GPT-2编码结构化上下文，通过字段特定MLP将化合物描述符、浓度、时间投射为嵌入插入文本序列。
  - Agentic MLLM (CP-Agent)：集成推理和工具使用，生成结构化报告；基于CP-CLIP输出的联合嵌入，结合MoA本体、领域工具（API/AI工具），通过思考和行动循环，生成包含实验设计建议和假设精炼的结构化报告。
- 算法细节：
  - 图像配对采样：从匹配的对照集Ω(x_p)中均匀采样对照图块x_c，与扰动图块x_p沿通道拼接。
  - 字段特定令牌注入：在文本序列中插入特殊占位符，通过MLP计算嵌入替换。
  - MLP结构：每个字段特定MLP包含线性层、GELU激活和线性层。
- 训练/推理细节：
  - 训练集：1,846,436图像-文本对，验证集：9,395对，零样本评估集：保留的化合物。
  - 使用三个公开数据集：BBBC021, CPJUMP1, RxRx3，涵盖约190万对。
  - 预训练在1.9M对数据上进行，采用对比学习方式。

### 5. Beyond Prompt-Based Planning: MCP-Native Graph Planning-based Biomedical Agent System
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2606.04494v1
- 方法流程：
  - 输入：自然语言生物查询q
  - 步骤1：将查询转换为结构化任务规范，包含生物实体、能力、数据类型和工作流约束。
  - 步骤2：通过GraphRAG检索全局MCP图，提取紧凑的任务特定子图，包含候选操作和路径提示。
  - 步骤3：LLM规划器基于检索的图上下文合成操作级工作流P = (o1, o2, ..., oh)，每个操作关联紧凑的候选工具集。
  - 步骤4：只动态注册和运行选定工作流涉及的MCP服务器。
  - 输出：最终执行轨迹。
- 关键模块/机制：
  - BioinfoMCP Compiler：将异构生物信息学工具自动转换为标准化MCP服务器；三阶段管线：准备阶段（从文档、手册等提取语义和执行规范）、执行阶段（LLM生成MCP服务器代码，自动解析和验证，迭代修正直到有效）、交付阶段（打包服务器、依赖和Docker环境）。
  - Typed Capability Graph：组织MCP生态系统为结构化图，提供规划骨架；六类节点：工具(T)、操作(O)、数据类型(D)、能力(C)、阶段(S)、MCP服务器(R)。边包括：implements（操作→工具）、consumes/produces（数据类型↔操作）、hosts（服务器→工具）、soft workflow-transition edges。图自动从MCP服务器构建，LLM推断数据类型、操作类别和工作流阶段。
  - Graph-Scaffolded Planner：基于检索子图生成操作级工作流；将查询转换为结构化语义锚点，通过GraphRAG检索子图。检索在操作级别进行，LLM合成操作序列P。每个操作绑定一个紧凑的候选工具集T(oi)，平均大小m̄ ≪ N。
  - Dynamic Execution：只注册和执行选定MCP服务器；工作流规划完成后，从全局MCP生态中动态选取涉及的服务进行注册和执行，避免加载全部工具。
- 公式/目标函数/指标定义：
  - 全局工具集T = {t1, t2, ..., tN}
  - 提示检索上下文大小：Cprompt = O(kℓ_t)，其中k为检索工具数，ℓ_t为平均工具描述长度
  - 图支架规划上下文大小：Cgraph = O(h(ℓ_o + m̄ ℓ_s))，其中h为工作流步数，ℓ_o为操作支架长度，m̄为每操作平均候选工具数，ℓ_s为工具模式长度
  - 上下文压缩比：在k=Θ(N)的高召回设置下，压缩比为Θ(N/(h·m̄))
- 算法细节：
  - GraphRAG检索：从查询中推断输入数据类型和目标，在图上游走获取相关操作子图。
  - 操作级规划：LLM基于子图上下文生成操作序列，避免直接处理原始工具描述。
  - 动态服务器注册：仅注册工作流涉及的工具的MCP服务器，减少推理时负载。
- 训练/推理细节：
  - 推理时：BioManus使用DeepSeek-V4作为LLM backbone，通过GraphRAG和LLM规划器生成工作流。无训练过程，仅推理。
  - BioinfoMCP Compiler使用LLM生成代码，需迭代验证直到语法正确。

### 7. Evaluating Large Language Models in Dynamic Clinical Decision-Making with Standardized Patient Cases
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2606.05112v1
- 方法流程：
  - 数据收集与预处理：从MedEdPORTAL检索标准化病人案例文章（1,073篇），筛选文本完整文章（1,017篇），使用MarkItDown和MinerU2统一转换为Markdown格式（7,147个文件）
  - 角色包构建：使用Codex（GPT-5.5）进行三阶段处理：①评估模拟性并提取元数据（613篇文章模拟有效，拆分为1,638个场景）；②划分内容到四个角色包（场景初始化、患者脚本、环境控制器材料、评分标准），通过复制-删除操作保持原文；③审计泄露和一致性，迭代修正
  - 评分标准解析：从评分标准包提取原始评分点（24,602条），逐字复制并映射到六项ACGME核心能力
  - 多智能体评估：临床智能体（待评估模型）与患者智能体（DeepSeek-V4-Pro驱动，根据案例脚本动态响应）和环境控制器智能体（管理时间演进和检查结果）交互，评估智能体根据完整轨迹计算完成率
- 关键模块/机制：
  - Codex数据策展管道：自动化地将原始教学文章转换为角色包，确保信息隔离和保真度；基于GPT-5.5的智能体系统，具备工具调用能力（Bash命令、Python解析）；三阶段：①评估文章是否可支持文本模拟，提取元数据并拆分多场景；②对每个场景执行复制-删除操作，将内容复制到四个角色目录后删除本角色不可见段落；③自我反思审计，检查角色包是否包含泄露信息、患者包是否足够、场景拆分是否一致
  - 多智能体评估框架：构建闭环交互环境，模拟临床动态；包含三个智能体：患者智能体（DeepSeek-V4-Pro，根据患者脚本动态生成符合当前阶段的中文响应）、环境控制器智能体（处理检查结果、时间演进，基于预定义临床状态序列驱动场景转移）、评估智能体（比较完整轨迹与评分标准，输出逐项判定）。交互流程：临床智能体输出动作→患者/环境响应→临床智能体接收新状态，循环直至场景结束
  - 评分机制：基于ACGME核心能力的过程级量化评估；对每个场景，将评估智能体判定的完成点除以总评分点得到场景完成率Rm = (Completed Points / Total Points) × 100%；总分为所有场景完成率的平均值（Total Score = Rm / Scenario Numbers × 100%）。评分标准直接源自原始教学材料，保证公平性
- 公式/目标函数/指标定义：
  - 场景完成率：Rm = (Completed Points / Total Points) × 100%
  - 总分：Total Score = Rm / Scenario Numbers × 100%
- 算法细节：
  - 复制-删除算法：Codex将源Markdown内容完整复制到四个角色目录，然后逐段判断是否属于本角色可见内容，删除不可见段落，保证所有文本可追溯至原文
  - 状态转移机制：环境控制器根据预定义临床状态序列（如初始表现、恶化、干预后状态）管理时间演进，当临床智能体标记当前状态完成时，检查是否满足转移条件，若满足则加载下一状态信息

- 方法流程：
  - 第一阶段：搜索空间定义，Θ = Θ_rewrite × Θ_chunk × Θ_ret × Θ_rerank × Θ_prune × Θ_gen，每个模块有离散超参数选项

  - Chunker：文档分块，控制块大小和重叠；超参数：chunk size ∈ {256,512,1024,2048}，chunk overlap ∈ {0,64,128,192}

  - Pruner：修剪上下文，控制输入长度；基于生成模块需求，对检索结果进行压缩或删除
  - Generator：生成最终答案；使用Qwen3系列LLM进行文本生成；多模态路径使用Qwen3-VL系列，结合CLIP检索视觉信息
- 公式/目标函数/指标定义：

  - 优化目标：θ* = argmax_{θ∈Θ} (1/N) Σ_{i=1}^N E(F_θ(q_i), Y*_i)，其中F_θ(q_i)为响应，E为评价函数
  - 评价函数E：等权组合ROUGE-L、METEOR、token-F1、BLEU
- 算法细节：
  - 控制器接口：算法通过提议配置θ_t并接收奖励r_t进行交互，支持异步并行评估
  - 实现了13种搜索算法，包括随机搜索、贝叶斯优化（SMBO）、Hyperband、BOHB、进化算法、EDA、bandit方法、RL风格方法等
  - 搜索空间离散化，每个超参数有固定候选值集合
  - 评估缓存：结果可复用，避免重复计算

### 19. Critic-R: Improving Agentic Search using Instruction-tuned Retrievers with Natural Language Introspective Feedback
- 区域：quick；分数：6.0
- 原文链接：https://arxiv.org/abs/2606.00590v1
- 方法流程：
  - 阶段1 - 轨迹收集：在训练集上运行Critic-R-Zero，收集每个检索步骤的智能体轨迹、批评者判断、细化尝试和最终结果。
  - 阶段2 - 监督池构建：将轨迹中满足智能体需求的文档标记为正例，将失败细化尝试中检索到的文档标记为硬负例（intra-trajectory negatives），同时从其他轨迹中采样批内负例。
  - 阶段3 - 对比训练：使用InfoNCE损失微调指令感知检索模型（如Stella-400M），正例与批内负例和硬负例进行对比，优化嵌入空间。
- 关键模块/机制：
  - 批评者模型 (Critic Model)：评估检索证据是否充分支持下一步推理；接收智能体的内省推理轨迹（消费检索证据后的思考内容），输出二元判断（满意/不满意）。基于预训练语言模型（如Llama-3.1-8B）实现，通过提示或微调获得评估能力。
  - 推理智能体 (Reasoner)：生成推理轨迹并发出检索动作；基于ReAct框架（如Search-R1），交替输出<think>和<search>动作。在Critic-R中冻结不变，仅负责生成查询和消费检索结果。
  - 指令感知检索模型 (Instruction-Aware Retriever)：根据查询和指令返回相关文档；使用Stella-400M作为骨干，编码查询和指令（如默认检索指令或批评者重写的指令），输出top-k文档嵌入。Critic-Embed通过对比学习微调该模型。
  - 查询重写模块 (Query Rewriter)：根据批评者反馈重写查询和检索指令；当批评者判定不满时，调用语言模型（可能与批评者相同或不同）基于当前查询、失败证据和批评者反馈生成新的查询和指令，用于下一轮检索。
- 公式/目标函数/指标定义：
  - InfoNCE对比损失：L = -log( exp(sim(q, d+)/τ) / (∑_{d- in negatives} exp(sim(q, d-)/τ) ) )，其中正例d+为满足智能体的文档，负例包括批内其他正例（作为负例）和intra-trajectory硬负例。
  - 查询相似度sim(q, d)采用点积或余弦相似度，温度τ为超参数。
- 算法细节：
  - Critic-R-Zero推理循环：对每个搜索动作，智能体生成初始查询q^(1)和默认指令I^(1)；检索得到D^(1)；智能体消费D^(1)并生成内省推理轨迹；批评者评估轨迹是否满意；若不满意，则基于当前查询、检索文档和批评者反馈重写q^(t+1)和I^(t+1)，重复检索-评估-重写，直到满意或达到预算上限。
  - Critic-Embed对比学习：在每批次中，取B个正例文档（来自不同轨迹），并附加intra-trajectory硬负例（如存在）。使用InfoNCE损失计算，正例与自身查询的相似度提高，与批内其他正例（视为负例）和硬负例相似度降低。
- 训练/推理细节：
  - 训练（Critic-Embed）：仅需在训练集上运行Critic-R-Zero收集轨迹，无需人工标注。轨迹中的正负例文档用于对比学习微调检索模型（Stella-400M）。批大小B=64，学习率2e-5。
  - 推理（Critic-R-Zero）：使用冻结的推理智能体、检索模型和批评者模型。每步检索后循环细化，最大重写次数设为3。批评者模型为Llama-3.1-8B，通过少样本提示进行评估。检索模型在测试时可选Critic-Embed微调版本。
