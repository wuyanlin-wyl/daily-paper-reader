## 摘要
临床智能体有望实现电子健康记录（EHR）的民主化访问，然而现有基准未能反映实际EHR分析的复杂性，例如，通常通过静态SQL生成在理想化、清洁的EHR上操作，而非交互式执行。在这项工作中，我们引入了EHR-Complex，一个专为交互式临床数据库推理设计的大规模基准。基于大型MIMIC-IV数据平台（365K患者、31张表、5亿+记录），EHR-Complex包含约52K个任务，涵盖六种临床意图，支持患者层面和人群层面的查询，每个任务要求智能体通过执行SQL查询或Python代码与沙盒环境交互。值得注意的是，EHR-Complex考虑了纵向多表聚合和组合推理的现实SQL任务复杂性，导致每个查询平均包含31.93个SQL结构组件。在EHR-Complex上的评估结果揭示了这些EHR推理场景的临床难度，最佳模型仅达到62.3%的精确匹配准确率。对于几乎所有评估模型，在k=4时Pass^k一致性下降到50%以下，揭示了广泛的随机脆弱性。对代表性LLM的超过3800条失败轨迹的细粒度分析揭示了三种主要失败模式：SQL逻辑错误、医学代码查找失败和语义误解。EHR-Complex为临床智能体提供了严格的测试平台，并突显了大规模EHR分析中稳健推理的剩余差距。

## Abstract
Clinical agents promise to democratize access to electronic health records (EHRs), yet existing benchmarks fail to reflect the complexity of practical EHR analysis, e.g., often operating on idealized, clean EHRs via static SQL generation rather than interactive execution. In this work, we introduce EHR-Complex, a large-scale benchmark designed for interactive clinical database reasoning. Built on the large MIMIC-IV substrate (365K patients, 31 tables, 500M+ records), EHR-Complex comprises about 52K tasks spanning six clinical intents, supporting both patient-level and population-level queries, where each task requires an agent to interact with a sandboxed environment by executing SQL queries or Python code. Notably, EHR-Complex considers the real-world SQL task complexity for longitudinal multi-table aggregation and compositional reasoning, resulting in 31.93 SQL structural components per query on average. Evaluation results on EHR-Complex reveal the clinical difficulty of these EHR reasoning scenarios, with the top-performing model achieving only 62.3% exact-match accuracy. Pass^k consistency drops below 50% for nearly all evaluated models at k=4, exposing broad stochastic fragility. A fine-grained analysis of more than 3,800 failed trajectories for representative LLMs reveals three dominant failure modes: SQL logic errors, medical-code lookup failures, and semantic misunderstandings. EHR-Complex provides a rigorous testbed for clinical agents and highlights remaining gaps in robust reasoning for large-scale EHR analysis.

## 2. 方法论：核心思想、关键技术细节与算法流程
### 核心思想
基于完整MIMIC-IV数据库（365K患者、31张表、5亿+记录）构建**患者事件图**，从中提取**临床证据路径**，进而编译为可执行SQL模板，并通过参数替换和自然语言重写扩展为大规模任务集。代理需要与沙箱环境交互（多轮SQL/Python执行）才能获得最终答案。

### 关键技术细节
1. **患者事件图构建**：为每位患者构建异构图 `Gp = (Vp, Ep, φ_V, φ_E)`，节点为临床事件（入院、ICU、化验、诊断等），边表示时序/语义关系。
2. **临床证据路径提取**：从图中采样符合时序一致性和临床合理性的有序路径 `P = (v1, v2, …, vk)`，构成推理链。
3. **证据到SQL模板**：使用LLM将证据路径映射为可执行SQL程序 `s`，经数据库执行验证（非空、确定性答案保留），共生成796个唯一结构模板。
4. **模板扩展**：每个模板通过重选患者、时间窗口、诊断代码等参数，并生成多个自然语言改写，得到约52K任务（48,092训练 + 3,915测试）。
5. **任务正确性公式**：每条轨迹 `τ` 的最终答案 `y` 与标准答案 `y*` 比较：`E(τ, y*) = I(y = y*)`。

### 算法流程（文字描述）
1. 输入自然语言查询 `x` 和数据库模式 `Σ`。
2. 代理在沙箱环境中多轮执行SQL/Python，接收执行反馈。

## 6. 主要结论与发现
- **整体挑战**：最佳模型（Kimi-K2.5和Qwen3.5-397B）仅62.3%精确匹配准确率，远低于实际部署需求。
- **人群级推理困难**：所有模型从患者级到人群级准确率大幅下降（如Kimi-K2.5从0.85降到0.40），人群级聚合对细微信号干扰极其敏感。
- **鲁棒性弱**：Pass^k在k=4时几乎所有模型低于50%，说明单次执行不可靠；Pass@k提升有限，表明部分任务仅能通过多次采样偶然成功。
- **三大失败模式**：SQL逻辑错误（41.1% GPT-4.1）、医学代码查找失败（32.1% GPT-4.1）、语义误解（37.9% Kimi-K2.5）。
- **SFT有效**：在EHR-Complex训练集上蒸馏Kimi-K2.5的成功轨迹微调，Qwen3-32B从0.36提升到0.55，超越GPT-4.1。
- **交互轮次需求**：大多数成功任务在10-15轮内完成，但更多轮次不一定提高成功率（存在死循环）。

## 7. 优点
1. **大规模真实数据**：基于完整MIMIC-IV（5亿+记录），覆盖真实临床复杂性。
2. **交互式执行**：突破静态SQL生成范式，模拟实际分析中的迭代调试过程。
3. **高任务复杂度**：平均每个查询31.93个SQL结构组件（AGG、JOIN、嵌套等），远超现有基准（如EHR-SeqSQL的17.03）。
4. **细粒度维度**：6种临床意图×2种查询范围，支持深入分析特定能力短板。
5. **人类验证**：对困难样本进行双人标注，确认95%有效，保证基准可信。
6. **失败分析**：详细分类并给出了代表性案例（附录G），揭示模型具体弱点，指导改进。
7. **开放贡献**：计划公开任务定义、SQL程序、评估环境、构建代码（需单独获取MIMIC-IV数据），促进可复现研究。

## 8. 不足与局限
1. **数据库单一**：仅基于MIMIC-IV（一家美国医院），其EHR模式、编码习惯、患者群体不代表全球临床环境，结果泛化性受限。
2. **未覆盖非结构化数据**：仅关注结构化表，忽略临床笔记、影像、实时交互等，限制了应用范围。
3. **无前瞻性部署**：基准限于实验室环境，未涉及真实临床工作流、隐私合规、延迟等实际部署挑战。
4. **任务构建依赖LLM**：模板生成用强LLM，尽管经执行和人类验证，仍可能引入偏差；部分语义边界（如时间“随后”的解释）可能存在模糊性。
5. **SFT实验限于域内**：仅在EHR-Complex训练集上微调，未测试跨机构或跨数据库的泛化（作者明确说明）。
