## 摘要
临床值集定义了用于质量测量、表型分析、队列构建和临床决策支持中的标准化术语代码。最近引入的检索增强集补全（RASC）基准表明，直接使用零样本大语言模型（LLM）生成并不适合此任务：临床代码系统庞大、有版本控制，且语言模型难以可靠记忆。我们研究了一种分阶段替代方案，其中候选池构建针对召回率进行优化，而受约束的LLM裁决器针对候选选择进行优化。在完整的3,744个值集RASC测试集上，基于Qwen3的检索结合词汇感知扩展和代码显示救援检索，将候选池召回率从原始RASC检索基线0.553提升至0.730；在保留发布者子集上，池召回率为0.655。仅靠高召回率池并不足够：将原始SAPBert交叉编码器应用于此扩展池，得到全测试集的宏平均F1为0.287，保留发布者子集的宏平均F1为0.233。将阶段2选择器替换为对同一池进行盲法GPT-5裁决，全测试集的宏平均F1提升至0.549，保留发布者子集的宏平均F1提升至0.533。这些结果表明，检索约束的LLM裁决能够显著改进值集补全，同时保持安全性约束：所有返回代码必须来自可审计的候选池。

## Abstract
Clinical value sets define the standardized terminology codes used in quality measurement, phenotyping, cohort construction, and clinical decision support. The recently introduced Retrieval-Augmented Set Completion (RASC) benchmark showed that direct zero-shot large language model (LLM) generation is poorly suited to this task: clinical code systems are large, version-controlled, and not reliably memorized by language models. We study a stage-wise alternative in which candidate-pool construction is optimized for recall and a constrained LLM adjudicator is optimized for candidate selection. On the full 3,744-value-set RASC test split, Qwen3-based retrieval with vocabulary-aware expansion and code-display rescue retrieval increases candidate-pool recall from the original RASC retrieval baseline of 0.553 to 0.730; on the held-out-publisher stratum, pool recall is 0.655. The higher-recall pool alone is not sufficient: applying the original SAPBert cross-encoder to this expanded pool gives full-test macro F1 of 0.287 and held-out-publisher macro F1 of 0.233. Replacing the stage-2 selector with blinded GPT-5 adjudication over the same pool increases full-test macro F1 to 0.549 and held-out-publisher macro F1 to 0.533. These results show that retrieval-constrained LLM adjudication can substantially improve value set completion while preserving the safety constraint that all returned codes must come from an auditable candidate pool.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 将临床值集自动编制视为**两阶段流水线**：
  1. **阶段1（检索/候选池构建）**：从已有值集库中检索相似值集，合并其代码，并利用词汇层次扩展和代码显示检索，构建高召回率的候选池。
  2. **阶段2（裁决/选择）**：对候选池中的每个候选代码，使用受约束的LLM（GPT-5）或交叉编码器（SAPBert）进行二元分类，决定是否应纳入目标值集。

### 关键技术细节
- **阶段1：候选池构建**
  - **语义检索**：用**Qwen3-Embedding-0.6B**编码值集标题，余弦相似度检索K=15个最近邻值集，合并其所有代码形成初始池。
  - **词汇感知扩展**：针对ICD-10-CM、RxNorm、SNOMED-CT三个词汇系统，利用层级/关系图进行局部扩展（每个种子最多加3个新代码，每个词汇最多加60个代码）。
  - **代码显示救援检索**：用BM25在代码显示字符串上检索目标标题，取每词汇前10匹配，并对其同样进行词汇扩展，以捕捉语义检索遗漏的代码。
  - 最终候选池 = 语义检索池 ∪ 词汇扩展池 ∪ 代码显示检索池。

- **阶段2：裁决模型**
  - **SAPBert交叉编码器**：原始RASC导出的分类器，不做再训练/阈值调优，作为保守基线。
  - **GPT-5约束裁决器**：通过Oracle Cloud Infrastructure的OpenAI兼容端点访问。输入为**盲法**结构（移除OID、发布者、标签等可泄露信息），包括目标标题、描述、代码系统、候选列表（含ID、代码、显示字符串、检索特征）。模型必须返回JSON格式的选中候选ID列表。候选池超过1200则分块处理，最终取并集。

## 6. 论文的主要结论与发现

1. **阶段1改进显著**：Qwen3检索+词汇扩展+代码显示检索将全测试集候选池召回率从原始RASC的0.553提升至0.730，OOD召回率从0.543提升至0.655。
2. **高召回池不足以保证下游性能**：SAPBert在原池上表现尚可，但扩展池上宏F1反而从0.298降至0.287（OOD仅0.233），说明直接扩大池带来更多假阳性，需要更强的选择器。
3. **GPT-5约束裁决大幅提升**：在相同扩展池上，GPT-5的全测试宏F1达0.549（OOD 0.533），相比SAPBert的0.287（OOD 0.233）提升约84%；池内召回利用率达0.757（全集）。
4. **安全性保持**：所有输出代码均来自可检索、可审计的候选池，避免了LLM幻觉导致的无效代码。
5. **OOD泛化能力优于传统交叉编码器**：GPT-5在留出发布者上表现稳健，表明其能适应不同的编制风格和概念分布。

## 7. 优点：方法或实验设计上的亮点

- **清晰的任务分解**：将值集编制分解为召回和选择两个可独立优化、可审计的阶段，便于追溯失败原因。
- **词汇感知图扩展**：利用医学词汇的层次/关系结构进行局部扩展，有效提升召回，且扩展上限可控。
- **代码显示救援机制**：通过BM25直接匹配代码显示字符串，弥补语义检索在标题不同时的失败，对OOD场景尤其有效。
- **盲法LLM裁决设计**：严格控制输入，防止LLM通过OID等泄露信息记忆结果，评估更公平。
- **发布者留出评估**：模拟真实的跨部署泛化场景，避免过拟合训练集发布者的编制习惯。
