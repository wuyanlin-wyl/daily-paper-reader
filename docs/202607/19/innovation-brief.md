### 1. Mixture of Cognitive Experts in Large Vision-Language Models
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2607.10796v1
- 方法流程：
  - 输入：图像I和查询q → 路由器（LLM引导）根据查询和粗粒度图像表示选择top-K相关视觉专家，输出专家索引集G
  - 阶段1：专家推理 → 根据G执行相应视觉专家（如DETR、SAM、Pix2Struct等），输出结构化感知输出O = {O^(e)}_{e∈G}
  - 阶段2：字面证据总结（Literal Evidence Summary） → 对每个专家输出O^(e)，通过言语化器v_e分解为原子化证据语句{(s_k, m_k)}，统一构建证据存储E = {e_i}，每个证据包含id, type（TEXT/ENTITY/REGION/TABLE/CHART）, text, ref
  - 阶段3：Bloom言语化（Bloom Verbalization） → 根据查询q和证据集E，按Bloom层次（LIST→EXPLAIN→ILLUSTRATE→COMPARE→HYPOTHESIZE→FINAL ANS）生成阶段性草稿答案y_Bloom，每步引用证据ID
  - 阶段4：最终答案生成 → 将y_Bloom作为额外上下文，与图像I和查询q一起输入LLM，生成最终答案ŷ = f_LLM(q, I, y_Bloom)
  - 可选并行：推理轨迹模块 → 解析y_Bloom和E，提取起始层级ℓ0、执行步骤集、每步引用证据及类型混合，用于定量分析
- 关键模块/机制：
  - Router (LLM-guided expert selector)：根据输入查询动态选择最相关的top-K视觉专家，避免执行所有专家，提高效率；构建路由提示，包含用户查询q、每个候选专家的简短描述（如OCR、检测、分割）、以及基础视觉编码器的下采样粗略图像表示。LLM生成短文本选择（如专家选项字母），解析为索引集G。仅执行G中的专家。
  - Adapter (Visual Expert Fusion)：将路由选择的专家特征融合到统一、LLM兼容的视觉表示中，增强基础视觉特征；采用L个堆叠块迭代细化基础图像特征X。初始X1 = X。每个块i，将路由的top-K专家特征{Fj}空间对齐到Xi分辨率（双线性插值），然后通过transformer子块处理融合表示得到Xi+1。L块后通过池化/残差头和MLP投影器输出专家增强的视觉token图，供LLM与查询及y_Bloom一同处理。
  - Literal Evidence Summary (字面证据总结)：将异构专家输出分解为原子化、统一格式的证据语句，作为后续推理的可信基础；对每个选中的专家e，定义言语化器v_e将O^(e)映射为{(s_k, m_k)}，s_k是简短字面陈述，m_k是元数据（如边界框、掩码ID）。所有语句归一化到统一证据存储E，每个元素包含id, type（TEXT/ENTITY/REGION/TABLE/CHART）, text, ref（指向源）。仅捕获字面感知事实，不进行推理。
  - Bloom Verbalization (Bloom言语化)：按照Bloom认知层次将证据集转化为结构化推理轨迹，提供可解释的中间推理步骤；定义有序Bloom步骤集L = [LIST, EXPLAIN, ILLUSTRATE, COMPARE, HYPOTHESIZE, FINAL ANS]。查询决定起始层级ℓ0∈L，然后执行从ℓ0到FINAL ANS的所有后续步骤。每步ℓ输出简短文本c_ℓ，并引用证据ID子集U_ℓ ⊆ {1..M}。所有步骤输出拼接为y_Bloom。例如：LIST仅枚举字面事实，EXPLAIN解释相关性，ILLUSTRATE给出示例，COMPARE对比假设，HYPOTHESIZE承诺最佳解释，最后给出答案。
  - Reasoning Trace Module (推理轨迹模块)：定量分析Bloom言语化输出的推理过程，提供可解释性度量和数据集级诊断；输入：y_Bloom（包含步骤标题和证据引用）和证据存储E。确定性解析提取起始层级ℓ0、执行步骤集、每步引用证据U_ℓ及对应类型。可聚合计算统计：各步骤出现比例、引用比例、平均引用数、进入层级分布。输出结构化轨迹记录。
- 算法细节：
  - 路由：基于LLM的指令遵循能力，通过提示包含描述和粗略图像表示，生成专家选择文本并解析为索引集。
  - 专家推理：并行执行选中专家，产生结构化输出（如边界框、OCR文本、分割掩码、表格数据）。
  - 字面证据总结：使用基于模板的言语化，将每个专家输出分解为多个原子化语句，每个语句带类型和引用指针。
  - Bloom言语化：由LLM根据查询和证据集生成分步推理文本，每步强制引用证据ID，步骤按Bloom层级顺序输出。
  - 推理轨迹分析：通过正则表达式或解析器提取y_Bloom中的步骤标题（如LIST:）和引用标记（如[E12]），与证据存储映射得到类型和数量。
  - 适配器融合：使用堆叠块，每块将专家特征通过插值对齐到当前特征图尺寸，再经transformer子块更新特征。
- 训练/推理细节：
  - 训练-free框架：所有组件在推理时执行，无需额外预训练或微调。
  - 推理流程：输入图像I和查询q → 路由器选择专家 → 专家推理 → 字面证据总结 → Bloom言语化生成y_Bloom → 将q, I, y_Bloom输入LLM → 输出最终答案。
  - 适配器使用预训练权重？原文未明确提及适配器是否需预训练，但说框架是训练-free，可能适配器使用现有模型的视觉投影器？实际实现中采用了[55]中的适配器，可能基于训练好的组件。
  - 所有视觉专家均为预训练模型（如DETR、SAM、Pix2Struct等），不更新参数。
  - LLM（Vicuna-7B）和CLIP视觉编码器使用预训练权重。

### 2. The Path to Self-Evolving Clinical Systems: Scaling Medical Agents from Assistance to Autonomy
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2607.11175v1
- 方法流程：
  - 输入：临床任务描述（如影像分析、报告生成）及多模态数据（图像、文本）
  - 阶段1：感知与推理——使用视觉语言模型（VLM）联合解释图像和文本
  - 阶段2：规划与记忆——基于POMDP框架进行序列决策，维护内部状态记忆
  - 阶段3：行动与环境交互——在临床环境（PACS、EHR）中执行操作，接收反馈
  - 输出：诊断建议、报告或干预措施，并记录经验用于自进化
- 关键模块/机制：
  - 环境缩放核心模块：集成工具、数据和临床健身房（clinical gyms），为智能体提供可交互的训练环境；构建PACS、EHR、FHIR生态系统的标准接口，支持如DICOM图像的获取与标注、结构化数据的查询与更新，以及模拟临床工作流的交互式环境。
  - 自进化机制：使智能体通过与环境的交互持续改进，而非仅依赖参数缩放；借鉴自改进智能体（self-improving agents）、智能体健身房（agent gyms）和测试时计算缩放（test-time compute scaling）的思路，通过在线学习、强化学习或反思循环更新策略。
  - 三级自主分类框架：界定医疗智能体的自主级别，指导系统设计与安全评估；辅助级（assisted）：智能体提供建议，人类完全决策；协作级（cooperative）：智能体与人类共同决策；全自主级（fully autonomous）：智能体独立决策并执行，仅在特定条件下报告。
- 公式/目标函数/指标定义：
  - 输入信息未提供明确公式
- 算法细节：
  - 序列决策形式化为POMDP，智能体维护信念状态（belief state），通过最大化累积期望回报选择动作
  - 利用VLM作为感知模块，将多模态输入映射为语义表示，并结合知识图谱或临床指南进行推理
  - 环境缩放涉及构建标准化的临床交互接口（如FHIR API），支持工具调用（图像检索、报告生成）
  - 自进化通过经验回放（experience replay）和参数更新实现，避免灾难性遗忘
- 训练/推理细节：
  - 训练数据来源：放射学报告、病理切片、眼底照片等临床数据集，结合合成数据以增强污染抵抗力
  - 训练策略：预训练VLM后，通过强化学习在临床健身房中微调，奖励函数基于诊断准确率和操作合规性
  - 推理时：采用链式思考（Chain-of-Thought）和多步推理，结合记忆模块存储历史病例
  - 测试时计算缩放：允许模型在推理阶段通过更多计算（如多次采样、树搜索）提升性能

### 3. Visual Access Boundaries in Vision-Language Model Reasoning
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2607.12815v1
- 方法流程：
  - 输入：图像和问题文本，使用VLM（如Qwen2.5-VL）生成回答（Direct或CoT）
  - 干预：在推理时，对每个层ℓ和已生成token索引τ，掩码该层及之后所有层中从所有生成token到图像token的注意力，同时控制已生成token的起始索引τ（即前τ个生成token不掩码）
  - 测量：在不同(ℓ,τ)组合下评估任务准确率，与全访问基线对比，计算准确率差ΔCoT(ℓ,τ)=Acc_masked - Acc_full
  - 定位：定义VAB为满足ΔCoT(ℓ,τ)≤ϵ的最小(ℓ,τ)区域（ϵ=0.05），ℓ*为最小层，τ*为最小token索引
  - 比较：对同一模型分别计算Direct和CoT的VAB，分析边界差异；跨模型家族和规模验证普适性
- 关键模块/机制：
  - Visual Access Sweep干预机制：因果干预工具，用于测量生成过程中图像token访问的必要性；在Transformer自注意力层中，对生成token的查询向量与图像token的键向量之间的注意力权重进行掩码。掩码沿两个维度：层深度ℓ（从最后一层往前）和生成时间τ（从最后一个生成token往前）。具体地，对于给定ℓ和τ，将所有层≥ℓ且所有生成token索引>τ的注意力掩码为负无穷，从而阻止该区域内的图像信息流动。通过逐步减少掩码区域，找到维持准确率的最小区域。
  - Visual Access Boundary (VAB) 定义与评估：核心度量，量化必要图像访问的深度和宽度；VAB由层边界ℓ*和token边界τ*构成。ℓ*定义为：当掩码所有高于ℓ*的层时，准确率仍保持在基线的ϵ内；τ*为类似的最小token索引。评估准则包括CoT-own-max（以CoT全访问为基线找自身边界）和direct-anchored（以Direct全访问为锚点，要求CoT掩码后准确率不低于Direct基线）。
  - 属性读取分析：解释CoT收益的瓶颈；通过符号属性Oracle（将真实属性作为文本输入）验证CoT能提升计数；通过单目标探测-解码检查，发现某些属性可从隐藏状态线性恢复但模型难以输出，证明读取瓶颈存在。
- 公式/目标函数/指标定义：
  - ΔCoT(ℓ,τ) = Acc_masked(ℓ,τ) - Acc_full_access
  - VAB: (ℓ*,τ*) s.t. for all ℓ≥ℓ* and τ≥τ*, ΔCoT(ℓ,τ) ≤ ϵ, with ϵ=0.05
  - |Δℓ*_own| = |ℓ*_CoT_own - ℓ*_Direct|
  - |Δℓ*_DA| = |ℓ*_CoT_DA - ℓ*_Direct|
- 算法细节：
  - Visual Access Sweep算法：首先生成完整回答并缓存所有层的注意力打分。然后从最大掩码区域（所有层掩码）开始，逐步减少掩码层或掩码token，在每一步计算准确率。具体做法是，对于每个候选(ℓ,τ)，在生成过程中动态修改注意力掩码矩阵，重新运行前向传播（但可复用已计算的键值缓存加速）。
  - 边界搜索采用网格扫描：层维度从0到L（总层数），token维度从0到T（生成总长度）。对于每个组合，计算准确率，等高线图确定边界。
- 训练/推理细节：
  - 仅涉及推理阶段干预，模型参数冻结，无需训练。
  - 所有实验使用预训练模型（Qwen2.5-VL 3B/7B/32B，InternVL3 8B/14B/38B，Llama-3.2-11B-Vision-Instruct），在zero-shot设置下进行。
  - CoT提示采用标准思维链格式，Direct提示为直接回答。

### 5. AspectCLIP: Optimizing CLIP Representation Space via Aspect-Guided Consistency Regularization
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2607.13805v2
- 方法流程：
  - 阶段1：方面感知语义聚类。使用SimCSE提取所有文本嵌入，K-Means聚类将M个样本划分为K个不相交的簇C_k，每个簇包含方面一致的图像-文本对。
  - 阶段2：批内采样与簇分配。每个训练批次包含N个样本，记录每个样本所属簇标签，统计各簇内样本数N_b^k。
  - 阶段3：组内循环一致性正则化。对每个簇内所有样本对（同一簇内），计算L_intra_C-Cyclic（跨模态循环）和L_intra_I-Cyclic（模态内循环），求和得L_intra。
  - 阶段4：组间原型级循环一致性正则化。计算每个簇的图像原型v_proto^k和文本原型t_proto^k。对每个样本，与所有其他簇的原型计算L_inter_C-Cyclic和L_inter_I-Cyclic，聚合得L_inter。
  - 阶段5：联合训练。总损失L_total = L_CLIP + λ1*L_intra + λ2*L_inter，同时优化全局对比学习和方面引导正则化。
- 关键模块/机制：
  - 方面感知语义聚类：将预训练数据划分方面一致的簇，作为后续正则化的结构基础；利用SimCSE提取所有文本嵌入，执行K-Means聚类（K=4），生成K个不相交的簇C_k。每个簇内的图像-文本对描述一致的视觉方面；跨簇样本描述不同方面。聚类仅基于文本，因为文本更可靠地指示方面。
  - 组内循环一致性正则化：对同一簇内所有样本对强制完整循环一致性，加强共享方面的几何对齐；在批内同一簇的所有样本对上，计算L_intra_C-Cyclic = (1/|S|) Σ ((v_i^k·t_j^k - v_j^k·t_i^k)^2) 和 L_intra_I-Cyclic = (1/|S|) Σ ((v_i^k·v_j^k - t_j^k·t_i^k)^2)。S为当前批次内所有簇内样本对的集合。
  - 组间原型级循环一致性正则化：在簇间仅用原型嵌入进行一致性约束，避免方面细节干扰，促进高层信息交换；计算每个簇的图像原型v_proto^k = (1/N_b^k) Σ v_i^k和文本原型t_proto^k = (1/N_b^k) Σ t_i^k。对每个样本(i,k)，与所有其他簇m≠k的原型计算L_inter_C-Cyclic = (1/(K-1)) Σ (v_i^k·t_proto^m - v_proto^m·t_i^k)^2 和 L_inter_I-Cyclic = (1/(K-1)) Σ (v_i^k·v_proto^m - t_proto^m·t_i^k)^2。最终L_inter为所有样本的平均。
- 公式/目标函数/指标定义：
  - CLIP损失: L_CLIP = (1/2)(L_I2T + L_T2I)，其中L_I2T = -(1/N)Σ log(exp(v_i·t_i/τ) / Σ_j exp(v_i·t_j/τ))，L_T2I类似。
  - CyCLIP全局循环一致性正则化（原文公式5和6）: L_C-Cyclic = (1/N^2) Σ_{i,j} (v_i·t_j - v_j·t_i)^2; L_I-Cyclic = (1/N^2) Σ_{i,j} (v_i·v_j - t_j·t_i)^2。
  - 组内循环一致性: L_intra_C-Cyclic = (1/|S|) Σ_{((i,k),(j,k))∈S} (v_i^k·t_j^k - v_j^k·t_i^k)^2; L_intra_I-Cyclic = (1/|S|) Σ_{((i,k),(j,k))∈S} (v_i^k·v_j^k - t_j^k·t_i^k)^2。
  - 组间原型级循环一致性: L_inter_C-Cyclic^(k,i) = (1/(K-1)) Σ_{m≠k} (v_i^k·t_proto^m - v_proto^m·t_i^k)^2; L_inter_I-Cyclic^(k,i) = (1/(K-1)) Σ_{m≠k} (v_i^k·v_proto^m - t_proto^m·t_i^k)^2。
  - 总损失: L_total = L_CLIP + λ1 * L_intra + λ2 * L_inter，其中L_intra = L_intra_I-Cyclic + L_intra_C-Cyclic, λ1=λ2=0.25。
- 算法细节：
  - 预训练前，一次性对整个预训练数据集进行文本聚类（SimCSE + K-Means），K=4，聚类结果作为静态标签。
  - 每个训练批次中，根据聚类标签统计各簇样本数N_b^k。对于簇内样本对，枚举所有可能组合（包括自身对？原文S定义包括i≠j？但公式(5)(6)中i,j从1到N，包括i=j？注意CLIP中i=j是正对，但循环一致性通常包括所有对。实际实现可能排除i=j以避免平凡解？但原文公式(10)(11)是和所有对。我们保留原文表述。
  - 组内正则化：遍历簇内所有样本对((I_i^k,T_i^k),(I_j^k,T_j^k))，计算两个平方差项，求和后除以|S|。
  - 组间正则化：先计算每个簇内所有样本嵌入均值得到原型。对每个样本，遍历其他K-1个簇的原型，计算两个平方差项，求和后除以(K-1)；再对所有样本平均。
  - 总损失反向传播更新模型参数，包括CLIP双编码器和温度参数τ。
- 训练/推理细节：

### 6. Beyond scalar losses: calibrating segmentation models via gradient vector field surgery
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2607.14338v1
- 方法流程：
  - 输入：原始区域损失函数（如Dice loss）的梯度向量场 ∇L_original
  - 计算预测误差：e = |p - y|，其中p为预测概率，y为真实标签
  - 梯度缩放：将原始梯度乘以预测误差因子 e，即 ∇L_new = e * ∇L_original
  - 使用缩放后的梯度进行反向传播
  - 输出：校准后的分割模型参数更新
- 关键模块/机制：
  - 预测误差计算模块：生成每个像素/体素的预测误差绝对值，作为梯度缩放的权重；对每个空间位置，计算预测概率p与真实标签y的绝对差，得到误差图 e ∈ [0,1]
  - 梯度缩放模块：将原始损失函数的梯度乘以误差图，实现逐像素梯度幅值调整；设原始区域损失函数L对模型输出logits的偏导为 ∂L/∂z，则修正后梯度为 ∂L'/∂z = |p-y| * ∂L/∂z，其中p = softmax(z)（二分类时）或sigmoid，y∈{0,1}
- 公式/目标函数/指标定义：
  - 修正损失函数梯度：∂L'/∂z = |p - y| * ∂L/∂z
  - 典型区域损失函数：Dice损失 L_Dice = 1 - (2∑p y + ε) / (∑p + ∑y + ε)
  - 校准评价指标：期望校准误差（ECE）
- 算法细节：
  - 训练过程中，每个batch前向传播得到预测概率图p，计算与真实标签y的绝对差图e
  - 计算原始区域损失函数L，自动求导得到梯度图g = ∂L/∂output
  - 逐元素乘以缩放因子：g_scaled = e * g
  - 使用g_scaled反向传播更新网络参数
  - 推理阶段不修改，正常前向得到概率图
- 训练/推理细节：
  - 训练阶段：梯度手术仅应用于反向传播，前向损失计算不变
  - 推理阶段：不引入任何额外操作，保持原始模型结构
  - 可与任何区域损失函数（Dice、Tversky、Focal等）直接结合

### 7. Reflex: Real-Time VLA Control through Streaming Inference
- 区域：deep；分数：9.0
- 原文链接：https://arxiv.org/abs/2607.14695v1
- 方法流程：
  - 1. 视觉流：VLM编码器持续以10-30Hz编码相机观测，并将KV对推入环形缓冲区的滑动历史区域
  - 2. 策略流：从环形缓冲区的静态前缀（指令）和滑动历史（观测）预合并KV缓存，动态后缀（流状态和timestep嵌入）每个去噪循环重置
  - 3. 分区注意力：在去噪循环中，仅对动态后缀计算注意力，静态前缀和滑动历史使用预缓存KV，输出与全批注意力等价
  - 4. 异步调度：线程A（视觉）持续编码并更新缓存；线程B（策略）独立运行动作生成，通过未来状态预测器用当前命令估计未来状态作为条件
  - 5. 未来条件状态对齐：用上一个执行的动作命令近似未来状态，以补偿异步延迟
  - 6. 动作执行：生成的动作块以50Hz发送给机器人执行
- 关键模块/机制：
  - 分区注意力（Partitioned Attention）：实现O(1)缓存更新的正确流式推理，避免全局timestep注入导致的KV缓存失效；将注意力上下文分为静态前缀（指令，永久计算一次）、滑动历史（最近N帧观测，FIFO更新）、动态后缀（当前流状态x(k)和timestep嵌入，每步重置）。注意力计算仅动态后缀需要重算，滑动历史采用增量预填充。实现手动缓存合并：在进入去噪循环前将静态前缀和滑动历史合并为连续内存，动态后缀使用预分配张量。
  - AdaRMSNorm：防止连续50Hz推理中BFloat16数值崩溃；输入x经FP32 RMS计算，再与门控γ(c)逐元素相乘：γ(c)=1+MLP(c)，c=[tk, st]为timestep嵌入和本体状态。方差计算强制FP32，门控MLP保持BFloat16。通过运行时探测输出投影层确定硬件精度，避免类型不匹配。
  - 异步流水线（Asynchronous Pipeline）：解耦视觉编码与动作生成，重叠计算缩短端到端延迟；线程A（视觉）作为生产者持续编码观测；线程B（策略）作为消费者使用最新缓存生成动作。使用未来状态预测器补偿异步延迟：用最后执行的动作命令acmd_t近似未来状态ŝ_{t+Δ}。自适应重叠调度根据实时推理延迟调整重叠步数K。
  - 算子融合（Operator Fusion）：减少内核启动开销，提升单流推理速度15-20%；将QKV投影融合为单一内核W_QKV=[W_Q;W_K;W_V]；将SwiGLU块的Gate和Up投影融合。
  - 环形缓冲区架构（Ring Buffer Architecture）：消除动态内存分配和碎片化，保证确定性延迟；预分配大小为L×N_max×H×D的连续张量，通过自定义指针算术循环索引，O(1)访问，零动态分配。
- 公式/目标函数/指标定义：
  - 分区注意力公式：Attn(x(k)) = Softmax( Q(k)[K_pin; K_slide(t); K_dyn(k)]^T / sqrt(d) ) × [V_pin; V_slide(t); V_dyn(k)]
  - AdaRMSNorm公式：AdaRMSNorm(x, c) = x / RMS(x) ⊙ γ(c)，其中γ(c)=1+MLP(c)，RMS(x)=sqrt( (1/d)∑_i x_i^2 + ϵ )
  - 未来状态预测公式：ŝ_{t+Δ} ≈ a_cmd_t （用上次执行的动作命令近似未来状态）
- 算法细节：
  - 增量预填充：仅对每个新观测帧编码并追加到滑动历史缓存，避免重算所有历史帧
  - 手动缓存合并：进入去噪循环前将静态前缀和滑动历史合并为连续内存张量，动态后缀预分配并每循环重置
  - 自适应重叠调度（Algorithm 1）：根据实测推理延迟τ_inf估计所需重叠步数K，在动作块执行到C-K步时异步启动下一块推理
  - 鲁棒数据类型推断：运行时通过探测输出投影层o_proj确定硬件计算精度（FP16/BF16），确保门控逻辑与骨干数据类型对齐
  - BFloat16精度保护：方差计算强制FP32，门控MLP保持BFloat16
- 训练/推理细节：
  - 推理：采用异步流水线，视觉编码线程以10-30Hz运行，动作生成线程以50Hz运行；未来状态预测使用当前命令近似，无需额外模型
  - 推理时使用分区注意力，确保输出与全批注意力等价（对于固定观测窗口和输入）
  - 数值稳定性：AdaRMSNorm在推理时动态调整激活分布，避免长时间部署下的数值崩溃
  - 算子融合和环形缓冲区在推理时生效，减少延迟和内存抖动

### 19. TVT-PAPD: Pathology-Aware Prototype Distillation for Self-Supervised Whole Slide Image Classification
- 区域：quick；分数：6.0
- 原文链接：https://arxiv.org/abs/2607.10406v1
- 方法流程：
  - 1. 输入整张WSI，将其划分为非重叠的P×P补丁，并计算补丁数N = (H/P)×(W/P)。
  - 2. 背景过滤：对每个补丁，若背景像素占比≥τ则丢弃，得到保留补丁集P。
  - 3. 补丁嵌入：使用Conv2D（核16，步长16）将每个补丁映射为D维嵌入，加上位置编码。
  - 4. TVT编码：将嵌入序列送入12层Transformer（16头，隐层1536维，MLP隐层3072），输出上下文感知的补丁表示。
  - 5. PAPD模块：计算学生和教师网络输出的表示与可学习原型库（大小为K）的注意力分布，然后计算两个分布间的KL散度作为蒸馏损失。
  - 6. 联合优化：总损失为DINO交叉熵损失与加权后的PAPD蒸馏损失之和，通过反向传播更新学生网络，教师网络通过EMA更新。
  - 7. 输出：训练完成后，取学生网络的特征用于下游分类。
- 关键模块/机制：
  - Tiny Vision Transformer (TVT) Backbone：作为自监督学习的骨干网络，从WSI补丁中提取上下文感知的特征表示。；由12个Transformer编码器层组成，每层包含16头多头自注意力，输入补丁经Conv2D嵌入（16×16）后投影到1536维，MLP隐层3072维，激活函数SiLU，总参数量90M。
  - Pathology-Aware Prototype Distillation (PAPD) Module：通过可学习原型库和蒸馏损失，强制病理相似区域学习一致表示。；包含一个可学习原型库P∈R^{K×D}，K为原型数量。对于学生和教师编码的特征Z_s、Z_t，计算softmax注意力A_s = Softmax(Z_s P^T)、A_t = Softmax(Z_t P^T)，然后最小化每个补丁位置i上两个分布的KL散度：L_proto = Σ_i D_KL(A_t^i || A_s^i)。
  - DINO Self-Supervised Framework：提供自监督训练的基础范式和教师-学生架构。；使用两套相同结构的网络（教师θ_t和学生θ_s），对同一输入的不同增强视图(v_s, v_t)分别编码，教师网络通过EMA从学生参数更新：θ_t ← mθ_t + (1-m)θ_s。DINO损失为教师软标签与学生输出间的交叉熵。
- 公式/目标函数/指标定义：
  - 补丁数量：N = (H/P) × (W/P)，H、W为图像高度和宽度，P为补丁大小。
  - 背景过滤条件：背景像素数(p_i)/P^2 < τ，保留补丁。
  - 补丁嵌入：z_i = E(p_i)，再添加位置编码：˜z_i = z_i + e_i。
  - DINO损失：L_DINO = - Σ_i p_t(x_i) log p_s(x_i)，其中p_t、p_s为教师/学生输出的概率分布。
  - PAPD蒸馏损失：L_proto = Σ_i D_KL(A_t^i || A_s^i)，A_t = Softmax(Z_t P^T)，A_s = Softmax(Z_s P^T)。
  - 总损失：L_total = L_DINO + λ L_proto，λ为平衡权重。
- 算法细节：
  - 1. 教师网络参数通过指数移动平均（EMA）更新：θ_t ← mθ_t + (1-m)θ_s，动量m通常接近1（如0.9995）。
  - 2. 原型注意力计算：对每个补丁表示z，计算其与所有原型的内积，经softmax归一化为注意力权重，表示该补丁在各原型上的成员概率。
  - 3. KL散度蒸馏：教师网络的注意力分布作为软目标，学生网络的注意力分布向其逼近，迫使学生保留病理模式。
  - 4. 联合优化：在每次迭代中，同时计算DINO损失和PAPD损失，求和后反向传播更新学生，再根据EMA更新教师。
- 训练/推理细节：
  - 训练使用单GPU，混合精度（mixed precision）以提升效率。
  - 采用梯度累积（gradient accumulation）处理大batch，适应显存限制。
  - 教师网络通过EMA更新，学生网络通过梯度下降优化。
  - 超参数：补丁大小224×224，背景阈值τ，原型数量K，平衡系数λ（具体值见表4，输入未提供）。
  - 推理时仅使用学生网络提取特征，用于线性分类或微调。

### 20. Agents Don't Just Agree, They Remember: Benchmarking Persistent Sycophancy in Stateful Personal Agents
- 区域：quick；分数：6.0
- 原文链接：https://arxiv.org/abs/2607.10526v1
- 方法流程：
  - Step 1: 构建基础项（100个，来自PersistBench 50个和ELEPHANT 50个）
  - Step 2: 对每个基础项应用4种场景框架（Personal-Opinion, Signed-Memory, Environment-Fact, Procedural-Workflow）和4种时间交付模式（All-at-Once, Progressive, Drip, Late Shock），生成1600个任务
  - Step 3: 持久阶段（5轮）: 用户提出带偏见的声明，智能体回应并可能写入持久状态（profile, memory, skill）
  - Step 4: 清除对话历史，开始查询阶段（3轮）: 进行中性查询（不提及之前声明），观察智能体回答是否受持久状态污染
  - Step 5: 使用LLM评判（6个维度）评估污染程度，计算Max-FR@3等指标
- 关键模块/机制：
  - 持久阶段（Persist Stage）：模拟用户引入偏见声明并允许智能体写入持久状态；5轮交互中，用户通过4种场景框架和4种时间交付模式提出声明，智能体可选择写入profile、memory或skill文件。写入操作由智能体自主决定，基准不预写任何记忆。
  - 查询阶段（Query Stage）：评估持久状态对中性查询的污染影响；在清除持久阶段对话历史后，启动3轮中性查询。任何污染必须来自持久状态文件。计算每轮查询的失败率（FR）和跨轮失败率。
  - 场景框架（Scenario Framing）：测试声明呈现方式对写入决策的影响；四种框架：Personal-Opinion（用户个人观点）、Signed-Memory（用户声称记忆）、Environment-Fact（环境事实）、Procedural-Workflow（可重用步骤）。不同框架赋予声明不同表面权威性。
  - 时间交付模式（Temporal Delivery）：测试声明强化和近因对写入的影响；四种模式：All-at-Once（第一轮全部给出）、Progressive（逐步增加细节）、Drip（分散在多轮）、Late Shock（最后一轮才给出关键声明）。
  - 写入模式分析（Write-time Pattern Analysis）：识别智能体写入持久状态时的三种偏见模式；状态提升：将用户观点提升为profile规则；归属移除：写入时去掉用户作为来源；范围扩大：将局部偏好写为全局规则。通过分析持久阶段写入的状态文件内容检测。
- 公式/目标函数/指标定义：
  - Max-FR@3: 每个任务中3轮查询中最大失败率（失败回答数/查询数）
  - Cross-turn FR: 至少一轮查询失败的比率
  - 下游失败率增量: 从session-only（45.0%）到commit后（71.9%）增加27.0个百分点
- 算法细节：
  - 任务生成：100个基础项（50 PersistBench + 50 ELEPHANT），每个生成16个变体（4场景×4交付），共1600个任务
  - 持久阶段：智能体与用户进行5轮对话，用户根据场景和交付模式提供声明；智能体自行选择是否写入持久状态文件（USER.md, MEMORY.md, SKILL）
  - 查询阶段：持久阶段结束后清除对话历史，启动3轮中性查询（与声明主题相关但不提及声明），智能体读取持久状态文件回答
  - 评分：使用LLM评判每个查询回答是否包含谄媚污染（6维度：Leak, Upgrade, Amplification, Persistence, Escalation, Sycophancy），综合计算Max-FR@3和Cross-turn FR
- 训练/推理细节：
  - 不涉及训练，仅评估预训练模型在PASB基准上的推理表现
  - 使用Hermes-Agent和OpenClaw两种智能体框架，每个框架支持12个模型（如Hermes-3, Claude等）
  - 运行环境为沙盒工作区，每个episode独立文件系统，持久阶段写入的文件在查询阶段可读
