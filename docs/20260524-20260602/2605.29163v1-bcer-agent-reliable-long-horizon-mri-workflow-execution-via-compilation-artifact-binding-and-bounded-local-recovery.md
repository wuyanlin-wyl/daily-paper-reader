## 摘要
许多最近的医学视觉语言模型和智能体研究是在2D图像或相对较短的工具调用交互上进行基准测试的，而实际的MRI分析通常需要处理3D/4D体积数据的长时间、相互依赖的流水线。在这些条件下，反应式工具调用智能体容易因错误的中期引用、不匹配的工具参数以及对跨步骤依赖的控制有限而引发级联故障。为了解决这个问题，我们引入了BCER（大脑-小脑-肢体-反射器），这是一种旨在实现可靠长时间跨度MRI工作流执行的控制器架构。BCER将高级规划与执行解耦，并提供有限局部恢复。我们在一个涵盖脑部、前列腺和心脏任务的多器官MRI基准上评估了BCER，该基准包含短链和长链工作流，并在不同控制器变体和多个骨干模型上使用了匹配的任务合同。与反应式基线相比，BCER在端到端执行方面取得了一致的改进，其中在长链工作流上观察到了最显著的增益。此外，BCER通过维护最终输出与中期构件及测量之间的显式链接，实现了可审计性。代码和基准已在https://github.com/Albertlongzi/BCER发布。

## Abstract
Many recent medical VLM and agent studies are benchmarked on 2D images or comparatively short tool-calling exchanges, whereas real MRI analysis typically demands long, interdependent pipelines that operate on 3D/4D volumetric data. Under these conditions, reactive tool-calling agents are prone to cascading breakdowns triggered by faulty intermediate references, mismatched tool arguments, and limited control over cross-step dependencies. To address this, we introduce BCER (Brain-Cerebellum-Extremity-Reflector), a controller architecture aimed at dependable long-horizon MRI workflow execution. BCER decouples high-level planning from execution and provides bounded local recovery. We assess BCER on a multi-organ MRI benchmark covering brain, prostate, and cardiac tasks with both short- and long-chain workflows, using matched task contracts across controller variants and several backbone models. Relative to reactive baselines, BCER yields consistent improvements in end-to-end execution, with the most pronounced gains observed on long-chain workflows. BCER additionally enables auditability by maintaining explicit links between final outputs and intermediate artifacts and measurements. Code and benchmark are released at https://github.com/Albertlongzi/BCER.

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出BCER（大脑-小脑-肢体-反射器）架构，将高层规划与执行解耦，并通过编译、符号构件绑定和有界局部恢复来增强长链工作流的鲁棒性。
- **关键技术细节**：
  - **Brain（大脑）**：从用户目标和可用MRI输入生成带约束的计划草图（plan sketch），仅描述执行步骤和约束，不直接执行工具或操作文件路径，留下部分字段待下游填充。
  - **Cerebellum（小脑）**：运行时控制器，将Brain的计划草图编译为可执行的工作流图。它检查接口和依赖约束，填充默认值，解析符号令牌（如 `@seq.*`, `@node.<id>.<field>` 等）绑定到具体值/路径，确保工具消费真实构件而非LLM生成的字符串。同时强制运行时约束（如案例范围/沙箱边界），按依赖顺序执行节点，记录状态/输出/错误的事件跟踪。
  - **Extremity（肢体）**：可执行工具层，提供标准化的MRI工具（数据I/O、预处理、分析、量化、报告），具有统一参数模式、类型化输出和标准化错误码。
  - **Reflector（反射器）**：处理运行时节点失败，执行有限局部恢复。优先尝试确定性修复，必要时调用受限LLM修复，仅重试失败节点或小型子工作流，保留上游成功结果，避免全局重启。
- **算法流程**（文字说明）：
  1. Brain根据输入 (V, M, g) 生成计划草图。
  2. Cerebellum将草图编译为工作流图，进行符号绑定和依赖解析。
  3. 按依赖顺序执行节点，每个节点调用Extremity中的工具，记录执行痕迹。
  4. 如果节点失败，Reflector检查错误，提出最小补丁，Cerebellum在相同约束下重试失败节点（或小型子工作流）。
  5. 最终输出包括任务产出和执行记录，支持从最终结论回溯到中间构件和测量。

## 6. 论文的主要结论与发现

- BCER在端到端执行可靠性上显著优于反应式基线，整体成功率从ReAct的65%提升到BCER的99%（TCR从74%到99%）。
- 最大的改进出现在长链任务上：前列腺报告任务从0/46提升到99/99，心脏报告从0/22提升到93/93。
- 添加Bind主要减少了低级引用和路径错误；添加Ref进一步抑制了执行错误但无法完全解决工作流结构缺失；BCER则通过编译阶段避免结构错误，使失败集中在工具或合同鲁棒性边缘。
- 该优势在不同骨干模型上均保持一致，表明执行控制机制比模型能力本身更关键。
- BCER同时保持可审计性，通过符号绑定和事件跟踪实现从最终输出到中间构件的显式链接。

## 7. 优点：方法或实验设计上的亮点

- **方法亮点**：

  - 有限局部恢复（bounded local recovery）仅重试失败节点，区别于全局重启，提升效率且保持上游结果。
  - 完整的可审计性设计，支持追溯。
- **实验设计亮点**：
  - 渐进式消融实验（ReAct → +Bind → +Ref → BCER）清晰归因每个组件的贡献。

  - 多器官、多模态、长短链任务覆盖全面，结论具有泛化性。
  - 探索了多个骨干模型，验证方法独立于特定LLM。
