## 摘要
临床诊断是一个主动寻求证据的过程，临床医生在此过程中获取证据、更新相互竞争的假设，并决定现有证据何时足以做出诊断。然而，许多围绕大型语言模型（LLM）构建的医学诊断系统仍将诊断表述为静态的病例到答案的预测，对证据获取的支持有限。智能体LLM通过工具使用和中间诊断轨迹提供了一种动态替代方案，但现有系统通常未充分说明如何在运行时暴露、搭建和控制患者证据。我们引入了EviDx，一种证据感知的主动诊断框架，将患者特定的诊断环境与临床诊断脚手架及观察者引导的运行时控制相结合。在EviDx中，$\mathcal{E}$-Synthesis从原始临床病例构建交互环境；脚手架组织角色专业化的智能体、证据工具和不断演变的证据状态；控制机制通过跟踪不确定性和证据覆盖率来规范诊断终止。一个三级评估金字塔评估执行稳健性、推理动态和诊断结果。实验表明，EviDx提高了诊断性能和过程稳定性，同时揭示了模型相关的能力边界。

## Abstract
Clinical diagnosis is an active evidence-seeking process in which clinicians acquire evidence, update competing hypotheses, and decide when the available evidence is sufficient for diagnosis. Yet many medical diagnosis systems built around large language models (LLMs) still formulate diagnosis as static case-to-answer prediction, with limited support for evidence acquisition. Agentic LLMs offer a dynamic alternative through tool use and intermediate diagnostic trajectories, but existing systems often under-specify how patient evidence should be exposed, scaffolded, and controlled at runtime. We introduce EviDx, an evidence-aware active diagnosis framework that pairs patient-specific diagnostic environments with a clinical diagnostic scaffold and an observer-guided runtime harness. In EviDx, $\mathcal{E}$-Synthesis constructs interactive environments from raw clinical cases; the scaffold organizes role-specialized agents, evidence tools, and evolving evidence states; and the harness regulates diagnostic termination by tracking uncertainty and evidence coverage. A 3-level evaluation pyramid assesses execution robustness, reasoning dynamics, and diagnostic outcomes. Experiments show that EviDx improves diagnostic performance and process stability while revealing model-dependent capability boundaries.

- **现有LLM诊断系统的缺陷**：目前围绕大语言模型（LLM）构建的医学诊断系统大多将诊断建模为**静态"病例→答案"预测**——模型一次性接收完整临床病例或选项集，直接生成诊断或选择答案。这种方式虽然能激发医学知识和最终答案，但**压缩了证据获取、证据整合和终止决策**，无法刻画主动诊断中的过程性失败（例如在证据不足时过早下结论）。
- **Agentic LLM的机遇与不足**：工具增强和智能体式医疗系统能够动态查询患者记录和外部医学知识，但**仅提供工具访问并不足以实现动态诊断**。LLM智能体的能力受三个层面制约：
  1. **环境**：如何暴露患者证据；
  2. **脚手架（Scaffold）**：如何组织证据操作、临床角色和证据状态；
  3. **运行时控制（Harness）**：如何监控执行并在证据不充分时阻止终止。
- **核心研究问题**：当交互式诊断环境与显式证据脚手架和运行时控制相结合时，临床LLM智能体能否变得更强大？
- **论文答案**：提出 **EviDx** 框架，将静态临床病例转化为交互式诊断环境，通过临床诊断脚手架组织角色特化智能体、证据工具和动态证据状态，并通过观察者引导的运行时控制来调节诊断终止，从而提升诊断性能与过程稳定性。

## 2. 方法论

### 2.1 总体架构
EviDx 包含四个核心组成部分：
- **E-Synthesis**（环境合成）
- **Clinical Dx Scaffold**（临床诊断脚手架）
- **Observer-Guided Harness**（观察者引导的运行时控制）
- **3-Level Evaluation Pyramid**（三级评估金字塔）

### 2.2 E-Synthesis：从静态病例到交互环境
- **Context Initializer** 处理原始临床文本，将其转换为**结构化患者数据**，并加载到 EHR Server 中；
- 将患者记录后端与证据访问工具耦合，形成交互环境 $\mathcal{E}_x$，使后续诊断行为可以查询患者特定记录和外部医学知识；
- **保留临床相关的模糊性、修饰词（qualifiers）和阴性发现**，避免结构化时丢失关键诊断线索。

### 2.3 Clinical Dx Scaffold：临床诊断脚手架
该脚手架结构化地组织LLM与环境的交互，包含以下角色与组件：

1. **Diagnostician（诊断医生）**：核心推理组件。
   - 维护鉴别诊断集合 $\mathcal{D}_t$、报告信念状态 $\hat{p}_t$ 和诊断轨迹 $\mathcal{T}_t$；
   - 每步更新鉴别诊断，决定下一步查询患者数据、咨询医学知识还是尝试终止；
   - 通过 Model Context Protocol (MCP) 工具调用标准化动作输出。

2. **EHR Executor（电子病历执行器）**：确定性访问 EHR Server，检索人口统计学、病史、实验室检查和影像报告等记录。

3. **Clinical Consultant（临床顾问）**：处理外部证据访问。对于知识导向的动作，使用**混合稠密检索（dense）+ BM25稀疏检索**（遵循 MedRAG）从知识服务器检索相关医学文献。

### 2.4 Observer-Guided Harness：观察者引导的运行时控制
- **动机**：即使智能体能请求证据，仍需运行时控制来判断当前轨迹是否可以终止。
- **诊断不确定性度量**：使用报告信念状态的**熵**：
  $$H(t) = -\sum_{d_i \in \mathcal{D}_t} \hat{p}_t(d_i | \mathcal{T}_t) \log_2 \hat{p}_t(d_i | \mathcal{T}_t)$$
  低熵表示信念集中，高熵表示鉴别诊断尚未解决。
- **运行时证据覆盖率**：
  $$V(\mathcal{T}_t) = \frac{|S_{\text{Queried}}(\mathcal{T}_t) \cap S_{\text{Available}}|}{|S_{\text{Available}}|}$$
  其中 $S_{\text{Available}}$ 为运行时 EHR 菜单暴露的所有可用部分，$S_{\text{Queried}}$ 为截至 t 步已通过工具调用访问的子集。该指标基于运行时可访问的元数据和工具调用轨迹进行**前瞻性**计算。
- **终止准则**：
  $$B(\mathcal{T}_t) = \big(H(t) < \tau_H(t)\big) \wedge \big(V(\mathcal{T}_t) > \tau_V(t)\big)$$
  只有当不确定性和证据覆盖率同时满足时，才批准终止。其中 **阈值是步骤感知（step-aware）的动态阈值**：熵阈值随交互推进逐渐放宽，覆盖率阈值在充分搜索后逐渐降低最低要求。此外，设置硬预算 $T_{max}$ 防止死循环。
- **算法流程**（Algorithm 1）：
  1. 从原始病例 x 合成环境 $\mathcal{E}_x$，初始化轨迹；
  2. 循环直到终止：Diagnostician 产生动作（查询患者数据 / 咨询顾问 / finish）；
  3. 若提议 finish，Observer Harness 检查终止条件，不满足则返回反馈并强制继续；
  4. 追加观察结果到轨迹，重复直至批准终止或达到 $T_{max}$。

### 2.5 3-Level Evaluation Pyramid（三级评估金字塔）

**Level 1: 执行稳健性（Execution Robustness）**
- **MCP Syntax Error**：工具调用格式错误（如 JSON 载荷格式错误、括号缺失、参数名幻觉）；
- **MCP Schema Error**：模型未能使用原生工具调用模式，而输出原始自然语言。

**Level 2: 推理动态（Reasoning Dynamics）**
- **不确定性收敛（Uncertainty Convergence, Unc.）**：归一化平均逐步熵：
  $$\text{Unc.} = \frac{1}{T} \sum_{t=1}^{T} \frac{H(t)}{H_{init}}$$
  分数越低表示信念状态收敛越快，但不等同于正确性或校准。
- **观察者干预（Observer Intervention, Obs.）**：记录 Observer 拦截的次数，描述过程控制信号。

**Level 3: 诊断结果（Diagnostic Outcomes）**
- **诊断准确率（开放式和多项选择）**：采用**渐进式双轨设计**——先开放生成诊断，再由LLM评判，最后进行多项选择评估，以减少选项消除启发式偏差。
- **参考证据召回（Acquisition 和 Cognition）**：区分"获取证据"与"推理利用证据"：
  - **Acquisition（Acq.）**：验证是否通过 MCP 工具将预定义参考证据成功检索进轨迹中；
  - **Cognition（Cog.）**：评估该证据是否被主动用于最终诊断推理中。

## 6. 主要结论与发现

1. **EviDx 提升了多选题诊断性能**：完整框架在多数数据集上取得最高 MC 准确率（如 Claude Sonnet 4.6 在 JAMA 上达 66%，在 DiagnosisArena 上达 52%）。对8B小模型提升最显著：Qwen3-8B 在 JAMA 上 MC 准确率从 18% 提升到 44%；Llama3.1-8B 从 17% 提升到 31%。
2. **执行稳健性存在显著模型差距**：GPT-5.2 和 DeepSeek-V3.2 零语法/模式错误；Claude 和 GLM 偶尔回退自然语言；8B模型频繁出现 schema 错误（Llama3.1-8B 超过500次），说明小模型在严格智能体环境中工具调用能力脆弱。
3. **Observer Harness 能阻止过早终止**：在不带 Observer 的情况下，智能体可能出现"虚假熵降"并过早下结论。Harness 通过熵与覆盖率双重条件拦截未充分探索的终止请求，引导继续获取证据。案例分析显示：Ministral3-8B 在无 Harness 时被阴性扫描误导诊断为 Crohn 病，有 Harness 时在阻断后继续查询并正确诊断为 Meckel 憩室。
4. **开放诊断的改善受限于基础模型医学知识**：小规模模型开放诊断准确率接近0%，说明脚手架和Harness能支持证据获取与假设排除，但**无法弥补参数化医学知识的不足**。
5. **证据召回与答案准确性存在张力**：小模型在 EviDx 下 Cognition 分数可能下降（如 Llama3.1-8B 在 JAMA 上从63.8%降至15.1%），因为单智能体会直接复制原始输入片段，而 EviDx 要求工具协调和观察整合，产生更压缩/改写后的轨迹。证据召回率应结合诊断准确率看待，而非替代指标。
6. **有限样本稳定性**：分层配对 bootstrap 显示 EviDx 相对 Single Agent 的平均 MC 增益一致为正（各模型增益约 +6 至 +12个百分点），Observer 特定增益较小且因模型/数据集而异。

## 7. 优点

1. **问题建模得当**：将临床诊断从静态预测重新定义为**主动证据寻求过程**，更贴近真实临床决策逻辑。
2. **框架分层清晰**：环境合成（E-Synthesis）、诊断脚手架（Scaffold）、运行时控制（Harness）三个层面解耦，分别对应"证据如何暴露""证据如何组织""何时终止"三个关键决策。
3. **终止控制机制具有创新性**：使用**动态、步骤感知的阈值**（熵阈值逐渐放宽、覆盖率阈值逐渐降低），避免静态阈值的僵化问题。
4. **三级评估金字塔设计合理**：同时评估"能否调工具""推理过程如何演化""最终诊断是否正确且是否用了正确证据"，弥补了仅看最终准确率的盲区。
5. **证据标注管线严格**：提取式（exact substring）标注 + 外部知识库锚定 + 医师抽查，降低LLM幻觉风险。
6. **对比实验严谨**：所有模型使用相同病例集、相同交互预算；提供 bootstrap 置信区间，且区分"获取证据"与"推理利用证据"双指标。
7. **消融设计有效**：通过 EviDx (wo Obs.) 对比可直接量化 Observer Harness 的贡献，说明其约束过早终止而非替代证据获取。
8. **案例分析细致**：完整呈现正面和失败轨迹，使机制透明、可解释。

## 8. 不足与局限

1. **样本规模有限**：每数据集仅100例，开放诊断和Obs干预的增益置信区间常跨越零值，统计功效有限；未报告全部数据上的结果。
2. **参考证据标注并非临床金标准**：Med-Evidence-2.6k 主要依赖 GPT-5.2 提取，医师审核仅覆盖100例子集（非完全独立、非盲审），只能作为 LLM 辅助参考基准。
3. **Harness 的过程信号是启发式的**：熵基于模型自报信念分布，证据覆盖率仅衡量已访问EHR部分的比例，**未与临床验证的终止标准对齐**。阈值调度（τH、τV）依赖启发式设置，缺乏理论依据或临床依据。
4. **伦理与安全约束**：
   - 不适用于真实医疗环境，不能保证临床安全；
   - 知识库主要反映西方临床指南，全球通用性受限；
   - LLM 可能输出有害建议，必须保持人类在场。
5. **缺乏多模态支持**：当前环境仅处理文本型EHR，未涉及影像、时序EHR轨迹、医患对话等富临床场景。
6. **模型依赖性强**：对小模型的改善主要体现在MC任务，开放诊断几乎无改进，说明框架无法弥补底层医学知识不足；这也限制了系统在低资源场景的可用性。
7. **评估主观性风险**：开放诊断由LLM评判器判定（relation_to_gt、entailed/partial等），存在评判偏差；多选题评估顺序（先开放后MC）虽减少选项启发，但可能引入记忆/学习效应。
8. **缺乏与其他医学智能体框架的定量对比**：Table 1仅为定性比较，未在同一数据集上对比 AgentClinic、MedAgentBench 等现有系统，难以定位 EviDx 在领域中的相对优势。
9. **算力与可复现性细节不完整**：未报告具体GPU型号和数量、总API调用量、推理耗时等，影响复现和成本评估。
