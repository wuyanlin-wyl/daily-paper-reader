## 摘要
开发具有竞争力的医学影像深度学习基线仍然是一个高度迭代的过程，需要文献综述、实现、实验和专家细化。现有的自动化方法通常优化孤立的组件，如架构搜索或超参数调优，而不是完整的基线开发过程。我们提出了一种智能体AI科学家工作流，结合文献引导推理、自动化代码生成和假设驱动实验，为医学影像挑战生成具有竞争力的基线模型。该框架在四个涵盖分割、分类和检测的公共基准上进行了评估。在所有任务中，实验流程持续提升验证性能，取得了具有竞争力的排行榜结果，包括在PUMA两个赛道（15支队伍）中均获得第6名，在MILK10k（125支队伍）中位列第31名。在MIDOG25上，所得模型还表现出跨扫描仪、肿瘤类型和物种的强领域泛化能力。我们在所有挑战中使用相同的工作流，无需针对特定任务重新设计，从而证明了基于技能、文献引导的智能体工作流可以大幅减少开发具有竞争力的医学影像基线所需的工程工作量。

## Abstract
Developing competitive deep learning baselines for medical imaging remains a highly iterative process requiring literature review, implementation, experimentation, and expert refinement. Existing automation approaches typically optimize isolated components, such as architecture search or hyperparameter tuning, rather than the complete baseline development process. We present an agentic AI Scientist workflow that combines literature-guided reasoning, automated code generation, and hypothesis-driven experimentation to generate competitive baseline models for medical imaging challenges. The framework is evaluated on four public benchmarks spanning segmentation, classification, and detection. Across all tasks, the Experimentation Pipeline consistently improves validation performance, achieving competitive leaderboard results, including 6th place on both PUMA tracks (15 teams) and 31st place on MILK10k (125 teams). On MIDOG25, the resulting model also demonstrates strong domain generalization across scanners, tumor types, and species. Using the same workflow across all challenges without task-specific redesign, we demonstrate that skill-based, literature-guided agentic workflows can substantially reduce the engineering effort required to develop competitive medical imaging baselines.

## 2. 论文提出的方法论

- **总体架构**：提出一个代理式AI科学家（agentic AI Scientist）工作流，包含三个顺序执行的流水线（Pipeline），由多个独立的、LLM驱动的“技能”（Skill）模块组成，每个技能有明确的输入和输出，交换结构化产物（Markdown、YAML、CSV）。
- **核心流程**：
  1. **数据描述与准备**：从原始数据集出发，Data Description技能生成结构化任务规范（含临床与机器学习双视角分析）；Data Preparation技能将原始文件转为标准化格式，并在可能时生成分组感知的数据划分（group-aware splits），否则使用可复现的图像级随机划分。
  2. **SOTA知识流水线（SOTA Knowledge Pipeline）**：结合问题特征化、文献分析和仓库代码审查，生成初始开发计划。它先识别临床问题、数据集特征、评估协议和变异性来源，形成研究问题；然后综合文献和挑战报告，对比模型架构、优化、增强、损失函数、评估等关键设计轴的证据；最终输出初始基线配置，并将不确定或有冲突的建议显式转化为实验假设。
  3. **模型设置流水线（Model Setup Pipeline）**：将开发计划转化为可执行的训练框架，自动生成数据加载与预处理模块、模型架构、优化策略、损失函数、评估指标，并集成到共享的PyTorch Lightning训练框架中。数据增强被有意排除，留待实验阶段优化。
  4. **实验流水线（Experimentation Pipeline）**：通过迭代的、证据驱动的科学实验流程优化基线。首先建立评估标准（官方挑战指标+次要指标）；通过学习率校准和RandAugment策略优化收集初始证据；增强策略搜索受限于图像检查和文献推导出的临床合理参数范围。后续实验由规则逻辑选择下一个评估组件、复用模板定义实验结构、LLM实例化假设与配置，每次尽量只修改单一设计决策。完成的实验更新持久化的实验计划与实验树（experiment tree），同时记录被接受和被拒绝的证据。
- **关键技术细节**：
  - 实验树保留正面和负面证据，不同于MLflow、W&B等传统实验追踪系统（它们主要记录产物和元数据而非结构化证据）。
  - 研究者在每个阶段通过轻量级审查检查点保持“人在回路”，但无需手动修改生成的建模代码。
  - 整个流程不依赖单一大型提示词，而是将开发过程分解为专业化技能模块。

## 3. 实验设计

## 8. 不足与局限

- **缺乏组件级消融**：论文评估的是完整工作流而非单个模块的贡献，无法判断文献知识流水线、模型设置流水线和实验流水线各自的独立价值。
