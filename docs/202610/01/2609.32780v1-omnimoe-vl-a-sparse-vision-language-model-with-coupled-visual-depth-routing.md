## 摘要
视觉语言模型（VLM）越来越多地使用稀疏专家混合（MoE）来扩展语言侧计算，但视觉信息通常仅在经过固定的跨模态接口之后才被路由。这留下了一个重要决策悬而未决：对于给定问题，哪些中间视觉表示应当暴露给语言计算？我们提出 OmniMoE-VL，一种带有耦合视觉深度路由投影器的稀疏 VLM。对于每个图像-提示对，该投影器选择一组稀疏的中间视觉深度，并复用由此得到的全局偏好来同时指导局部 patch 融合和向语言模型中的动态视觉注入。该设计在保留原生视觉 token 序列的同时实现了依赖问题的视觉访问，并补充了视觉和语言堆栈中的 token 级专家路由。在八个基于图像的基准上，OmniMoE-VL 以 28B 总参数和 9B 激活参数取得了 85.9 的平均分。受控比较表明，路由式视觉接口提供了主要的架构增益，而匹配的路由与组件控制、同图像路由分析以及路由干预进一步支持了耦合与以问题为条件的视觉访问的价值。

## Abstract
Vision-language models (VLMs) increasingly use sparse mixture-of-experts (MoE) to scale language-side computation, yet visual information is typically routed only after passing through a fixed cross-modal interface. This leaves an important decision unresolved: which intermediate visual representations should be exposed to language computation for a given question? We introduce OmniMoE-VL, a sparse VLM with a coupled visual-depth routed projector. For each image-prompt pair, the projector selects a sparse set of intermediate visual depths and reuses the resulting global preference to guide both local patch fusion and dynamic visual injection into the language model. This design enables question-dependent visual access while preserving the native visual-token sequence, and complements token-level expert routing in the vision and language stacks. Across eight image-based benchmarks, OmniMoE-VL achieves an average score of 85.9 with 28B total and 9B activated parameters. Controlled comparisons show that the routed visual interface provides the dominant architectural gain, while matched route and component controls, same-image route analysis, and route interventions further support the value of coupling and question-conditioned visual access.

## 一、核心问题与研究动机

- **背景**：视觉语言模型（VLM）越来越多采用稀疏专家混合（MoE）来扩展语言侧计算能力，通过将每个 token 分配给少量参数专家来实现“容量—计算”权衡。
- **核心矛盾**：现有稀疏 VLM 的视觉信息通常在**经过固定的跨模态接口之后**才被路由。也就是说，语言侧路由器只能决定“如何处理已暴露的视觉 token”，却无法决定“哪些视觉表示应当被暴露”。
- **被忽视的关键决策**：视觉编码器不同深度的中间表示承载不同类型的证据——浅层保留局部外观与文字细节，中层将相邻 patch 组织为物体，深层提供更广的上下文结构。密集投影器或固定视觉流在语言路由器介入前就把深度轴合并掉了，语言路由器无法恢复未被暴露的视觉流。
- **问题的可检验性**：同一张图面对不同问题时，理想的视觉来源应随问题变化；若用另一个问题诱导的路由替换原路由，应损害预测。这构成了论文的核心假设。
- **整体含义**：论文主张将“条件计算”从 token 级参数专家路由，扩展为**样本级、以问题为条件的视觉源访问决策**，作为稀疏 VLM 的互补维度。

## 二、方法论

### 核心思想
OmniMoE-VL 将 token 级视觉/语言专家与一个**样本级视觉深度投影器**结合。对每个图像—提示对，投影器稀疏选择若干中间视觉深度，并**复用同一全局偏好**同时指导局部 patch 融合与语言层动态注入，形成“一次显式源选择、两处协同使用”的结构。

### 关键技术细节

- **多深度视觉流提取**：从视觉编码器第 1, 5, 9, …, 37 块（共 S=10 个流）抽取对齐 patch 位置的特征。
- **提示条件化查询参与**：
  - 一个可学习的 16 个原型库 C 对提示嵌入做交叉注意力，得到 16 个提示条件化原型 q_i 及参与权重 p_i。
  - 采用概率下限 ε_q=1e-4 保持所有原型可用；引入长度自适应参与目标：有效参与数 n_eff(p)=1/Σp_i² 应逼近 n_tgt(L_T)=clip(log(1+L_T)+4, 2, Q)，并用平方损失 L_q 监督。
  - 由软权重 p 经学习矩阵 M 合成 R=8 个路由器查询 t_r。
- **全局深度选择**：
  - 每个深度流经投影得到语言宽度特征，路由器查询对其做注意力读出并打分 r_s。
  - 推理时通过 TopKSoftmax 取 top-4 得到全局路由 w（10 维稀疏分布）。
  - **早期训练探索**：对历史使用率做高斯核平滑得到有序先验，并加入“欠使用奖励”b_s(c) 鼓励探索；探索期 12,000 步后关闭。
- **组局部 patch 融合**：
  - 将 patch 划分为连续 32 个 token 的组，组内计算局部兼容性得分与全局先验的对数和：g_b = TopKSoftmax4(⟨v_b,s, t̄⟩/τ_g + log max(w_s, ε_w))。
  - 按 g_b 加权融合各深度特征，拼接各组后**恢复原生 patch 序列**（384×384 输入对应 576 个 token，18 个组），不扩展语言输入长度。
- **路由式语言层注入**：
  - 对提示与每个视觉流分别做注意力池化得到文本方向 U 与视觉方向 B_s，配对相似度经 softmax 得系数 β_s；构造秩 r_T=32 的变换 T_s = B_s diag(β_s) U^T。
  - 经秩 r_G=32 的学习适配器 G_ℓ 映射到固定锚定层 a(s)=s，**用同一 w_s 加权**后以残差形式注入语言层：h ← h + η·w_s·G_s T_s h。
  - 因子化评估避免稠密 d×d 矩阵，组合秩不超过 min(r_T, r_G)=32。
- **共享路由的学习**：两条路径通过语言建模损失共同训练 w，梯度同时来自融合后的视觉 token Z 和注入变换 A_ℓ。

### 训练流程（四阶段）
- Stage I：仅训练投影器，对齐视觉—语言骨干；
- Stage II / III：分别训练语言专家、视觉专家；
- Stage IV：以更低学习率联合微调全部模块。

- **Benchmark（8 个）**：MMBench、MM-Vet、TextVQA、DocVQA、POPE、MMMU、OCRBench、ChartQA，覆盖多模态理解、文字识别、文档、物体幻觉、多学科推理、图表等。
- **对比方法**：

## 六、主要结论与发现

- **性能**：OmniMoE-VL 以 28B 总参数、9B 激活参数在八个基准上平均 **85.9**，超过 Qwen2.5-VL-7B（81.2）4.7 分（+5.8%），其中 MMMU 提升 11.5 分（+19.6%）、MM-Vet 提升 11.2 分（+16.7%）。
- **架构增益来源**：从 LLM-only MoE（80.3）到路由投影器（85.2）再到完整模型（85.9），**路由式视觉接口贡献了主要增益（+4.9~6.1 分）**，视觉专家再补 0.7 分。
- **耦合优于独立**：共享深度偏好比融合/注入独立路由高 **1.1 分**（83.7 vs 82.6）；普通 softmax 门控低 1.9 分，标准负载均衡/UCB 路由低 0.6 分，逐层 LoRA 低 0.4 分。
- **组件必要性**：移除查询控制降 3.8%，移除注入降 4.3%，同时移除查询控制与结构化路由降 5.1%。
- **问题条件化验证**：同图不同问题的路由 TV 距离（0.301）显著大于改写（0.162），差距 0.139；即便参考答案相同，差距仍为 0.072。
- **路由干预**：替换为他题路由使参考答案 NLL 上升（融合 0.04、注入 0.03、联合 0.09 nats/token），而改写路由仅上升 0.01。
- **鲁棒性**：下采样+模糊下 LLM-only MoE 掉 4.8%，投影器变体仅掉 1.4%，完整模型掉 0.9%。
- **部署代价**：吞吐比 Qwen3-VL-8B 低 11.1%，峰值显存高 372.7%。

## 七、优点

- **问题定位清晰且新颖**：把“哪些中间视觉深度应暴露给语言计算”显式建模为一个可路由的源访问决策，区别于传统 token 级专家路由。
- **一次选择、两处复用的耦合设计**：同一全局偏好 w 同时服务局部 patch 融合与语言层注入，避免两个稀疏模块各自为政，实验证明耦合优于独立。
- **保留原生 patch 序列**：融合后仍是 576 个 token，不增加语言输入长度，计算开销可控。
- **训练稳定性设计**：有序历史先验 + 欠使用奖励促进深度探索，探索期后关闭，推理时纯内容驱动。
- **实验严谨性**：匹配参数量/秩对照、同图路由分析、路由干预、退化鲁棒性、利用率分析等多角度验证，并配有理论分析（如命题 1、命题 2、注入残差传播界）。
- **坦诚报告代价**：明确给出显存与吞吐的劣势，未回避部署成本。

## 八、不足与局限

- **训练算力不透明**：未报告训练 GPU 数量与时长，难以评估训练成本与可复现性。
- **部署开销显著**：52 GB 峰值显存、吞吐下降 11.1%，28B 全专家存储对硬件要求高，实际落地门槛较高。
- **模型对比不完全对等**：部分外部模型的 Avg. 基于不同数量的 benchmark（3~8 项），跨模型平均分直接比较存在偏差风险；Qwen3-VL-8B 等仅覆盖部分任务。
- **依赖特定骨干**：实验固定使用 SigLIP2-Giant + Qwen3-8B，路由设计在其他视觉编码器/语言模型上的泛化性未验证。
- **路由分析规模有限**：问题条件化分析仅基于 397 张 GQA 图像（322 组改写、283 张图），样本量与场景多样性有限，统计显著性未报告。
- **深度选择范围固定**：仅从 10 个固定块（1,5,…,37）抽取，top-4 稀疏度也固定，未探索不同深度密度或自适应 k 的影响。
- **理论分析较浅**：附录 C 的命题主要刻画 softmax 形式、秩与范数界，未给出路由最优性或泛化性保证。
- **潜在偏差**：训练数据来源集中于 LLaVA 系指令数据，基准去重虽已做，但仍可能存在与评测分布相关的隐性偏差。
